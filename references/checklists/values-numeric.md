# values-numeric checklist (NUM)
Covers `src/values/number.rs`, `length.rs`, `percentage.rs`, `angle.rs`, `time.rs`, `resolution.rs`, `ratio.rs`, `position.rs`, `size.rs`, `rect.rs`, `src/values/mod.rs`, and every property that parses or prints through them. Spec: `references/spec/syntax-values.md` §3 (anchor keys in §0).
Top failure modes: hand-rolled number serialization (double `-` in scientific notation #899/#1097/#1219, i32 saturation since #1200, f32 6-digit precision #949); unitless numbers parsed as px (#1199); unit or zero normalization that changes the type or the context (`0px` -> `0`, `x` -> `dppx` #1286).
`[open #N]` / `master FAILS` marks a pre-existing bug: answer FAIL only if head is worse than base, extends it to new inputs, or claims the fix while the probe still fails.

- [NUM-01] (BLOCKER) Every serialized negative value has exactly one `-` in every numeric type (number, dimension, percentage, angle, time, resolution), including scientific notation and |x| < 1, and a fix to one serializer covers every copy of the trim logic (regressions #899 -> #901 numbers, #1097 -> #1192 dimensions; master FAILS [open #1219] for percentages: src/values/percentage.rs:66-71 prints `-1e-7%` as `--10e-8%`).
  verify: probes values-numeric/community-prs-negative-scientific-number, values-numeric/community-prs-negative-scientific-dimension, values-numeric/negative-scientific-percentage-no-double-hyphen, values-numeric/issues-b3-negative-sci-percentage, values-numeric/issues-b0-negative-tiny-percentage-serialization; O3 (`--…` is rejected); R2.
- [NUM-02] (MAJOR) No new precision loss: values keep the digits the engine would use, integers keep every digit where `int_value` is known, and a PR that changes number formatting lists and justifies each changed expectation (master FAILS [open #949, #12, #170]: f32 printed with 6 significant digits, src/values/number.rs:122-142: `123456.75px` -> `123457px`, `1234567ms` -> `1234.57s`).
  verify: probes values-numeric/ssv-fractional-length-precision, custom-properties/ssv-custom-property-integer-precision; T3/T4 on changed expectations; `lcr show` text, because the oracle's number tolerance max(0.002, 1e-4 x value) classifies this drift as noise.
- [NUM-03] (MAJOR) A unitless non-zero number is never accepted as a `<length>`, and the PR adds no new caller of that leniency; a fix keeps literal `0` valid and leaves `width:10` as Unparsed so the earlier valid declaration survives (V4#deprecated-quirky-length; master FAILS [open #1199, #682, #1042]: src/values/length.rs:145-147 maps `Token::Number` to px).
  verify: probes values-numeric/ssv-unitless-length-invalid, values-numeric/unitless-nonzero-length-not-px, values-numeric/ssv-unitless-translate-invalid, values-numeric/issues-b1-unitless-number-non-quirky-context, values-numeric/devon-unitless-length-standards-mode, custom-properties/ssv-property-initial-value-unitless; O7 `invalid-became-valid`.
- [NUM-04] (BLOCKER) Integral values outside the i32 range print their value (at f32 precision), never a saturated 2147483647 or -2147483648, and every hand-built cssparser `Token` carries a correct `int_value`/`has_sign` (regression v1.33.0: `serialize_dimension` passes `Some(value as i32)`, src/values/length.rs:518, after #1200; `rotate:3000000000deg` -> `2147483647deg` turns 120deg into 127deg; same class: u16 palette indexes, src/rules/font_palette_values.rs:191).
  verify: probes values-numeric/ecosystem-consumers-large-integral-value-no-i32-saturation, values-numeric/community-prs-percentage-int-value-serialization, font/sft-font-palette-values-large-integers; realworld deltas (daisyUI `3.40282e38px`).
- [NUM-05] (MAJOR) Literal out-of-range values stay invalid (`Property::Unparsed`, so the browser validates and the earlier value survives) for every range, not only `[0,∞]`: `font-weight [1,1000]`, `<integer [1,∞]>` such as `column-count`, `span -1`; literals are rejected, not clamped (fixed for `[0,∞]` by #1329 `NonNegative`; master FAILS for `font-weight:1001`; open PR #304 accepts `column-count:-123456789000` as `-2147483648`).
  verify: `property_range_test(&[...], &[(input, None)])` cases in the PR; probe calc-math/ssv-out-of-range-calc-font-weight; O7 `invalid-became-valid`.
- [NUM-06] (MAJOR) Unit canonicalization (ms to s, rad to deg, grad, turn, `x` and `dppx`, Q) happens only in typed contexts whose grammar accepts the result for the targets, never context-free inside token lists or `image-set()` (regression dcbb9b8 v1.17.0 [open #1286]: `image-set(... 2x)` and `--s:2x` -> `2dppx` for old targets, PR #1384; src/values/resolution.rs:85-91; `1x` must stay in image-set, #264).
  verify: probe gradient-image/issues-b5-image-set-x-unit-in-token-list; mutations retarget-legacy, retarget-modern; output-contains on the original unit.
- [NUM-07] (MAJOR) A zero length keeps its unit wherever the property also accepts `<number>` (`line-height`, `tab-size`, `border-image-width`/`-outset`, a lone flex basis, `@property <number> | <length>`, keyframes) and inside math functions; unitless zero is printed only in pure `<length>` slots (master FAILS: src/values/length.rs:493 prints `line-height:0px` as `0`, which makes the animation discrete; INV-NUM-002/003).
  verify: probes values-numeric/ssv-line-height-zero-interpolation, custom-properties/ssv-property-number-or-length-zero, calc-math/ssv-unitless-zero-inside-math, flex-grid-align/devon-flex-unitless-zero-basis.
- [NUM-08] (MAJOR) A change to a shared value type (`Position`, `DimensionPercentage`, `NumberOrPercentage`, `Size2D`, `Rect`, `serialize_dimension`) lists every property and function that uses it and shows the new form is valid in each grammar (the 3-value `<position>` exists only in `background-position`; master FAILS for `transform-origin` z offsets, src/properties/mod.rs:1474; #1124 one-value position forms).
  verify: S1 and `prepare.json` radius_areas; probe transform/ssv-transform-origin-keywords-z; O7 for each touched property directory.
- [NUM-09] (MAJOR) `0%` is not rewritten to `0`/`0px` where it changes behavior (percentage heights with an indefinite basis, cyclic percentages, grid tracks, flex-basis); a `<position>` rewrite that only changes the computed string (`0% 0%` -> `0 0`) is classified with V4#combine-mixed (INV-NUM-004).
  verify: O1 on `height`/`flex-basis` probes whose `dom:` gives an indefinite basis; the "0% vs 0px inside position" false-positive bucket (references/spec/syntax-values.md §6).
- [NUM-10] (MAJOR) `<integer>` slots keep non-integer tokens (`1.0`, `1e3`, `1.5`) invalid, and `calc()` stays as written until integer calc rounds half toward +∞ and keeps relative units unresolved (src/values/number.rs:217 has no calc; open PR #1122).
  verify: probes calc-math/ssv-integer-calc-not-unwrapped, printer-serialization/wpt-engines-token-number-type-flag-kept.
- [NUM-11] (MAJOR) Every unit or keyword newer than the targets is wired to its compat feature in `IsCompatible`, so an author fallback before it (`height:100vh;height:100dvh`) is kept for each target that lacks it, with desktop browser numbers (src/values/length.rs:183-205; handler fallback preservation reads `targets.browsers` directly; src/compat.rs gives desktop Opera the Opera Android dvh version, 73 instead of 94; master FAILS, unfiled: `rex`/`rch`/`rcap`/`ric` have no feature in `define_length_units!` at src/values/length.rs:363-482 although src/compat.rs defines `RexUnit`..`RicUnit`, so `width:10px;width:1rch` drops the fallback for Safari 16).
  verify: probe box-model-size/browser-compat-opera-desktop-dvh-fallback-kept; write a probe `.t{width:10px;width:1rch}` (lower-minify, safari 16, `output-contains:"10px"`); mutations retarget-legacy, engine-legacy-2021 (no dvh); O4; B11.
- [NUM-12] (MAJOR) Zero and default checks in serializers are semantic (`is_zero()`), never structural equality with a px zero, so `0rem`/`0em` from visitors or conversions print like `0px` ([open #981]: TextShadow src/properties/text.rs:1438-1445; same pattern in box_shadow.rs and effects.rs).
  verify: a probe or visitor test with `0rem` components; read the diff for `== ...::zero()` and `!= NonNegative::zero()`.
- [NUM-13] (MINOR) Exponent notation is emitted only where every target parses it (Chrome 43, Firefox 29, Safari 10.1) and never ahead of a unit that starts with `e` plus a digit (INV-NUM-006, INV-SER-001).
  verify: retarget-legacy output; probe printer-serialization/em-dimension-unit-e-digit-not-exponent.
- [NUM-14] (MINOR) Shortened numeric forms parse in the targets: `<ratio>` `a / 1` -> `a` only where the single-number form is supported (media `aspect-ratio` has no target check, [open #379]), and `x` only where supported (INV-SER-006).
  verify: write a probe `@media (aspect-ratio: 1/1)` in mode lower; O3 in engine-legacy-2021 and engine-legacy-2023.
- [NUM-15] (NOTE) Values are f32 throughout (Firefox also stores lengths as f32, Chrome doubles), and the maintainer treats 6 significant digits as browser-equivalent (#807, #917), so a precision-only delta needs a visible effect (layout units, angles mod 360, integers) to count as a regression.
  verify: references/spec/syntax-values.md §6; O1 at layout-unit granularity; `lcr show`.
