# background checklist (BG)

Covers `src/properties/background.rs` (BackgroundHandler: `background` shorthand and longhands, `background-clip: text` prefixing) and the shared `src/values/position.rs`. Spec: `references/spec/images-effects.md` §2 and §4 (D5, D21, INV-BG-*, INV-GEN-001). Images inside layers also need the IMG checklist.
Top failure modes: position shortening that is invalid in some consumer (#771, #1124); invalid values made valid and deduped over a valid fallback (color in a non-final layer, `background-clip: border`, empty or unitless values); declarations reordered around `var()`, prefixed images and unowned aliases (D21, `-webkit-background-size/-origin`).
Items describe head output. A `known: open-issue#N` or `open-bug` probe that is `still-different` on base and head does not FAIL an item unless the PR claims that bug.

- [BG-01] (BLOCKER) `<position>`/`<bg-position>` parsing and serialization stay valid and equivalent in every consumer of `Position` (`background-position`, `background` layers, `mask-position`, gradient and shape `at`, `transform-origin`, `perspective-origin`, a future typed `object-position` #1047): 3/4-value forms keep keywords before offsets (`center bottom 1px`, #771), shortened forms are emitted only where that grammar accepts them, and a parse change does not widen what non-background consumers accept.
  verify: INV-BG-006; probe background/background-position-three-value (fixed-by#1124); other consumers: transform/transform-origin-keywords-z, transform/sat-transform-origin-four-value-invalid, gradient-image/radial-three-value-position-invalid, effects-masking/mask-position-three-value-invalid; prepare.json blast_radius for position.rs:59-300 must list the gradient, shape, masking and transform callers; WPT background-position and mask-position parsing files (O7); O3; https://drafts.csswg.org/css-values-4/#position-serialization
- [BG-02] (MAJOR) `background-clip: text` lowering emits `-webkit-background-clip: text` after the shorthand for the targets that need it (Chrome 4-119, Safari 3.2-13, iOS 4-13; prefixes.rs:786-825), keeps the unprefixed value, and keeps an authored `-webkit-background-clip: text` whenever a target still needs it.
  verify: master prints `background:url(a.png);-webkit-background-clip:text;background-clip:text` for chrome 100 (exact); mutations engine-legacy-2021, engine-legacy-2023 (Chromium 97/110 need the prefix) -> O4; prefixed-sibling, retarget-none, retarget-modern; history #325 (closed upper bounds, fixed by #326) and the Safari/iOS 13 override in build-prefixes.js (B11: regenerated, not hand-edited); Android WebView 5+ gets no prefix (residual of #1180; same mechanism as probe prefixing-compat/android-webview-mask-prefix)
- [BG-03] (BLOCKER) Invalid background values stay invalid (unparsed) and the earlier valid declaration survives: a color in a non-final layer, `background-clip: border` (old draft; the keyword is `border-area`), an empty `background:` (must not become `0 0`), a 3-value position outside `background-position`, unitless non-zero lengths (`background:333333`, `background-size:10 20`).
  verify: INV-BG-002/007, INV-GEN-002; probes background/background-color-in-non-final-layer-is-invalid, background/background-clip-border-keyword-invalid (Chrome maxdiff 255; background.rs:364 TODO, `BackgroundClip::Border` :236), values-numeric/unitless-number-non-quirky-context (open-issue#682: `background-color:red;background:333333` -> `background:333333px`); `background:green;background:` -> `background:0 0` on master; WPT css/css-backgrounds/parsing/background-invalid.html (`red, green`) and background-clip-invalid.html (`border`) via O7 `invalid-became-valid`; mutation reverse-decls; https://drafts.csswg.org/css-backgrounds-3/#background
- [BG-04] (BLOCKER) Background declarations keep their cascade order relative to `var()`/unparsed and vendor-prefixed background declarations: a prefixed-image declaration (`background: -webkit-linear-gradient(...)`) is not re-appended after a later `background-image: var(...)`, and an unparsed shorthand or longhand flushes the buffered values first.
  verify: INV-BG-009; probe background/prefixed-gradient-decl-moved-after-var (fails on master when an unprefixed `background` follows the prefixed one: `self.decls` re-appended at finalize, background.rs:818-831, 915-923); mutations var-before, var-after, reverse-decls, prefixed-sibling -> O1; #580 (static `background-color` kept before `var()` while `color` is dropped: both safe until `revert-rule`)
- [BG-05] (MAJOR) Color and image fallbacks for `background`, `background-color` and `background-image` (lab/oklch/p3 to rgb, gradient fallbacks, prefixed gradient copies) appear once, before the authored value, only for targets that need them; an earlier author fallback is dropped only when the later value is compatible with every target; prefixed gradient copies follow IMG-01/IMG-02.
  verify: BackgroundHandler `flush!` is compat-aware only for color and images (background.rs:833-839); mutations retarget-none (no fallbacks), retarget-legacy, engine-legacy-2023 -> O4; R2 (no duplicate fallbacks on a second pass); probe gradient-image/prefixed-gradient-default-direction-minify (open-issue#1107, reached through `background-image: linear-gradient(...), image-set(...)` for chrome 100)
- [BG-06] (BLOCKER) Longhands are collapsed into `background` only when every list has the same layer count (otherwise exact longhands, background.rs:974-983), and expanding or collapsing never changes a layer: `none` layers stay layers, lists repeat or truncate to the `background-image` count, `background-size: X` equals `X auto`.
  verify: INV-BG-004/005; PR tests with `test()` and `minify_test()` pairs; shorthand followed by a later image longhand (`background:url(x);background-repeat:repeat;background-image:linear-gradient(red,red),url(x)` expands to exact longhands on master, EM-47); mutations reverse-decls, duplicate-nonadjacent -> O1; https://drafts.csswg.org/css-backgrounds-3/#layering
- [BG-07] (BLOCKER) Properties that `background` resets but BackgroundHandler does not own keep their source order relative to `background`: the Compat §3.4.1 properties `-webkit-background-size` (a near-alias: one value sets both sizes in Blink/WebKit) and `-webkit-background-origin` (supported by every engine), `background-blend-mode`, `background-position-inline/-block`, `background-repeat-x/-y`, `background-tbd`. (`-webkit-background-clip` is typed and owned.)
  verify: INV-GEN-001; master already hoists `-webkit-background-size/-origin` before a deferred `background` (`background:url(a.png);-webkit-background-origin:content-box` -> origin first, so the shorthand resets it: verified with the base adapter and in Chrome 156, Firefox 157, WebKit 27.2; no issue or probe yet) and `background-blend-mode`; a PR must not add to this list; declaration.rs:583-611 pushes unowned properties immediately; probe input shorthand then longhand plus mutation reverse-decls -> O1; no oracle engine resets `background-blend-mode` (the spec does: https://drafts.csswg.org/compositing-1/#background-blend-mode), so decide that one against the spec
- [BG-08] (MAJOR) Box keywords keep their meaning: one box sets origin and clip, two set origin then clip; `(origin padding-box, clip text)` may print as `text` (Chrome keeps origin `padding-box`), but `border-area` is never emitted alone for an origin other than `border-box`.
  verify: INV-BG-003; background.rs:497-515; `background: red content-box border-box` round trip (passes on master, EM-45); O9 if Firefox/WebKit apply the L4 rule (a clip-only value sets origin `border-box`); https://drafts.csswg.org/css-backgrounds-4/#background
- [BG-09] (MAJOR) If the change dedupes or merges entries of one background list, every sibling list (image, position, size, repeat, attachment, origin, clip, blend-mode) is re-indexed so each layer keeps its own values.
  verify: INV-BG-004; same failure shape as #850 (merged `transition-property` entries left durations misaligned, v1.28.2; probe transition-animation/transition-property-prefixed-alignment); mutation duplicate-nonadjacent; multi-layer probe with distinct values per layer -> O1/O6
- [BG-10] (MAJOR) Shorthand/longhand rewrites do not introduce side-relative or logical longhand forms (`background-position-x: right 10px`, `x-start`, `-inline`) for targets without them (side-relative `-x/-y`: Chrome < 144).
  verify: INV-BG-008; mutations retarget-legacy, engine-legacy-2021, engine-legacy-2023 -> O3/O4; background.rs:278-324; BCD css.properties.background-position-x side-relative values
- [BG-11] (MAJOR) New typed background syntax (`border-area`, `repeat-block/-inline`, `x-start/x-end`, `background-tbd`, `plus-lighter` in `background-blend-mode`) follows the backgrounds-4/compositing-2 grammar exactly and stays unparsed or behind a flag where engines lack it (GEN-02).
  verify: BCD: `border-area` Chrome 150, Safari 18.2; `x-start/x-end` Safari 26 only; `plus-lighter` in background-blend-mode Firefox preview only; WPT css/css-backgrounds/parsing (O7); https://drafts.csswg.org/css-backgrounds-4/#typedef-bg-clip
- [BG-12] (MINOR) The all-initial `background` prints a valid value (`none` pretty, `0 0` minified, background.rs:517-525), and any other initial-value shortening keeps the same per-layer longhand values.
  verify: `background:none` and `background:transparent` round trips; a computed `background-position` delta `0% 0%` vs `0px 0px` from this is render- and interpolation-equivalent (EM-46): classify ACCEPTABLE_SIDE_EFFECT citing https://drafts.csswg.org/css-backgrounds-3/#background-position
