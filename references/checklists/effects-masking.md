# effects-masking checklist (FX)

Covers `src/properties/masking.rs` (MaskHandler: mask*, mask-border*, `-webkit-mask-box-image*`; clip-path parsing), `effects.rs` (filter, backdrop-filter, mix-blend-mode), `box_shadow.rs`, `src/values/shape.rs`, opacity, and the FallbackHandler/PrefixHandler paths in `prefix_handler.rs` that own filter, backdrop-filter and clip-path (load this list when that file changes too). Spec: `references/spec/images-effects.md` §6 (D1, D3-D5, D17, D18, D22, D24, D25).
Top failure modes: prefixed/unprefixed pairs collapsed by FallbackHandler (#537, #695, #1086, #1229, #1327, #977, #1360); mask longhands, prefixes and mask-border reordered or duplicated around the deferred `mask` (#504, #969, D1, D3); invalid values made valid (D5) and color-fallback panics (#721, #800, #1311).
Items describe head output. A `known: open-issue#N` or `open-bug` probe that is `still-different` on base and head does not FAIL an item unless the PR claims that bug.

- [FX-01] (BLOCKER) `backdrop-filter`/`filter` and their `-webkit-` forms survive in both orders: the unprefixed declaration is never replaced by the prefixed one (Chrome and Firefox never supported `-webkit-backdrop-filter`), the prefixed one is kept or generated whenever a target needs it (Safari 9-17.6, Edge 17-18; `-webkit-filter` Chrome 18-52, Safari 6-9), and different per-vendor values stay distinct (#977).
  verify: INV-FILTER-007; probes effects-masking/issues-b5-backdrop-filter-unprefixed-kept (open-issue#1327), prefixing-compat/issues-important-backdrop-filter-standard-then-webkit (open-issue#695), prefixing-compat/issues-b1-unprefixed-backdrop-filter-dropped (open-issue#977), prefixing-compat/issues-important-backdrop-filter-webkit-kept-for-safari (fixed-by#94f254c, #537); root: FallbackHandler overwrites the slot with its prefix (prefix_handler.rs:116-121, since 2694a18 v1.21.0; open PRs #1259/#1284 conflict); mutation prefixed-sibling only inserts prefixed-first, so the unprefixed-first order needs its own probe; an O9 split "equivalent in webkit, different in chromium/firefox" is a REGRESSION (WebKit links both names); https://drafts.csswg.org/filter-effects-2/#BackdropFilterProperty
- [FX-02] (BLOCKER) An earlier author `filter`/`backdrop-filter` declaration is dropped only when the later value is supported by every target (a real `IsCompatible` over `drop-shadow()` colors, lengths and each function), and generated color fallbacks are produced for every declaration that needs them, not only the first occurrence.
  verify: probe effects-masking/pr1364-filter-fallback-kept (open-issue#1360; fails on master: `filter:blur(1px);filter:drop-shadow(0 0 2px oklch(…))` for chrome 90 keeps only the oklch filter; `FilterList::is_compatible` returns `true`, effects.rs:410-414; PR #1364); fallbacks only for the first occurrence (prefix_handler.rs:101-114, same mechanism as color/arch-props-values-second-lab-declaration-gets-no-fallback); mutations engine-legacy-2021, engine-legacy-2023 (Chromium 97/110 lack oklch) -> O4

  verify: probe prefixing-compat/issues-b1-mask-image-var-duplicate (open-issue#969; unparsed branch masking.rs:700-707; PRs #1295 and #1339 conflict in masking.rs); R2; mutations var-before, prefixed-sibling, retarget-legacy; history #237 (6b15754: `Url` equality included the source location), #238 (713ce2e), #403; Devon on #1339: merge into `dest.last_mut()`, no backward scan
