# css-modules checklist (MOD)

Covers CSS modules: `src/css_modules.rs` (Config, Pattern, hashing, exports and references, `handle_composes`), `src/properties/css_modules.rs` (`composes`), `src/values/ident.rs` (CustomIdent/DashedIdent printing), the printer hooks `write_ident`/`write_dashed_ident` (src/printer.rs:290-350), `:local()`/`:global()` and pure mode in `src/selector.rs`, and the config plumbing in napi, the CLI and the C bindings.
Top failure modes: (1) an ident position is not renamed, or a global or reserved name is renamed (#883, #762, `:state()` names, `match-element` #1256, `counter()` arguments); (2) exports, references or generated names drift (order #291/#1355, naming #129, `DefaultHasher`); (3) rule-level minification drops CSS-module semantics (`composes` lost to duplicate removal, `:global` merging and `:is()` folding #900/#1032/#1079).
Evidence: oracle L8 skips CSS-modules cases and mutations skip every request with CSS modules (lib/lcr/mutations.py:271); the adapter sorts exports by name and returns no references (adapter/lcr_adapter.rs:217-224), so order and references come from the PR's `css_modules_test` and `test_css_module_order`.

- [MOD-01] (BLOCKER) Every new or changed ident printer decides scoping explicitly and consistently: local names (classes, ids, `@keyframes`/`animation-name`, `@counter-style`/`list-style-type`/`counter()`/`counters()`, grid lines and areas, container names, view-transition names and classes, dashed idents when `dashedIdents` is on) are hashed at the definition and at every reference; global or reserved names (`:state()` names, `match-element`, `auto`, `none`, CSS-wide keywords, the view-transition `root`) are never hashed.
  verify: PR `css_modules_test` asserting CSS and exports for definition and reference; probes css-modules/community-prs-state-pseudo-not-hashed, css-modules/view-transition-name-match-element-not-scoped, css-modules/sat-view-transition-root-name-not-scoped, css-modules/issues-b0-nth-child-of-selector-renamed, css-modules/em-counter-function-style-argument-renamed; read `CustomIdent::to_css` vs `to_css_with_options(dest, false)` in the diff (#883 #1133 #1256 #194 #124 #129).
- [MOD-02] (BLOCKER) Rule-level minification keeps CSS-module semantics: duplicate-rule removal does not drop an earlier rule's `composes` (the dedupe key compares property ids only, src/rules/style.rs:152-171), rules with `:global()`/`:local()` are neither folded into `:is()` around pseudo-elements nor merged on cached selector flags, and rules from different source files are not merged.
  verify: PR test `.a{composes:b} .x{color:red} .a{composes:c}` asserting that `a` composes both (unfiled; reproduced on 1.33.0 with minify off too); probe css-modules/issues-b2-global-list-pseudo-element-not-folded-into-is; GEN-08 (#900 #1032 #1079).
- [MOD-03] (MAJOR) Values containing `var()` or `env()` (Property::Unparsed token lists) are renamed wherever the typed value would be, or the PR states the gap: unparsed `animation` names are rewritten by the AnimationHandler during `minify()`; grid-template idents next to `var()` (#762) and `var(--x from "f")` inside functions or nested rules (#763, #854) are open bugs.
  verify: a PR test of the same value with a `var()` member; probe with `flags: css-modules` and `output-contains:` the hashed name.
- [MOD-04] (MAJOR) Exports and references keep their contract: `CssModuleExport { name, composes: [Local | Global | Dependency { specifier }], isReferenced }` (src/css_modules.rs:222-259), IndexMap order equals source order (#1355, 987e1bf, first released in v1.33.0), no export for a name that is not local, `var(--x from "./f.css")` recorded in `references` and `from global` left bare.
  verify: expected exports and references in the PR's `css_modules_test`; test_css_module_order (src/lib.rs:311-344); bundler::tests::test_css_module; B5 when napi changes (Vite sorts the keys itself because of #291; Next.js concatenates `composes[].name`).
- [MOD-05] (MAJOR) Generated names are stable unless the PR is a declared naming change: the hash input (path relative to projectRoot, `[local]`, `[content-hash]`), pattern segments and encoder are unchanged, and a toolchain bump leaves names unchanged (`std::hash::DefaultHasher` is not stable across Rust releases, src/css_modules.rs:538-549; dependency placeholders use the same `hash()`, src/dependencies.rs:76, :111).
  verify: T4 on css_modules_test tuples (no hash changes); B1 with the head toolchain (#129 renamed every class in patch release v1.7.4; Windows path PRs #1120/#1247; #351).
- [MOD-06] (MAJOR) CSS-modules-only syntax and errors are gated on `css_modules.is_some()`: `composes`, `:local()`/`:global()`, `var(--x from …)`, `global()`, the `@value` error and pure-mode lints change nothing when CSS modules are off.
  verify: the PR's new inputs without `css-modules` give identical base and head output (probe without the flag); probe transition-animation/pr860-global-fn-without-css-modules (#784, Devon in review: "Should we only error if CSS modules are enabled and just pass it through otherwise?"; PR #860; #575).
- [MOD-07] (MAJOR) A new config option reaches every entry point with a default equal to current behavior: `css_modules::Config` (src/css_modules.rs:30-49), napi `CssModulesConfig` for both transform and bundle (`unwrap_or(true)`, napi/src/lib.rs:731-734 and :862-865), the CLI (src/main.rs:137-141), C (`..Default::default()`, c/src/lib.rs:286-290), `CSSModulesConfig` in node/index.d.ts (:317) and website/pages/css-modules.md.
  verify: B5; B10 runs only when `c/` changed, so build `-p lightningcss_c_bindings` whenever Config gains a field (#739 broke the C crate from 1.25.0 to 1.27.0); read each site (#835 `container`).
- [MOD-08] (MAJOR) `composes` rules hold: allowed only in a single simple class selector (`InvalidComposesSelector`), never nested (`InvalidComposesNesting`, src/declaration.rs:202-213), class names parsed as identifiers rather than `<custom-ident>` (so `composes: default` works), and unresolved local names keep today's silent behavior unless the maintainer decides otherwise.
  verify: `css_modules_test`/`css_modules_error_test` in the PR; probe css-modules/issues-b0-composes-class-named-default (#908 and PR #909; #1215 open, PR #1216 makes it a breaking error).
- [MOD-09] (MAJOR) Pure mode stays exact: `is_pure_css_modules_selector` (src/selector.rs:2264-2280) requires a local class or id, nested children of a pure parent are exempt (`.foo { div {} }` passes, `html { .foo {} }` does not), every return path restores `context.pure_css_modules` (the early return at src/rules/style.rs:98-100 skips the restore, so later siblings bypass the lint when `unusedSymbols` empties a rule; unfiled), and `/* cssmodules-pure-no-check */` counts only among the leading comments (src/stylesheet.rs:172).
  verify: `minify_error_test_with_options` cases in the PR; a PR test with `unusedSymbols` plus nested rules (#796, #889, #898).
- [MOD-10] (MAJOR) Patterns produce valid names that match the exports: `[local]` ends the pattern when grid scoping is on (`InvalidCssModulesPatternInGrid`), a name that would start with a digit is escaped or gets the `_` prefix (src/css_modules.rs:538-549), and each exported name equals the name printed in the CSS.
  verify: test_project_root (src/lib.rs:28174-28205), css_modules_test with custom patterns, CLI `css_modules_pattern` test (#129 #180 #802 `[content-hash]`).
- [MOD-11] (MAJOR) Multi-file output hashes each name with its own file: the printer hashes with `Printer.loc.source_index`, which only `add_mapping` updates and only with the `sourcemap` feature (src/printer.rs:243-246), bundled `composes … from` dependencies keep the first instance, and exports of `@import`-ed files are not re-exported (#1034).
  verify: bundler::tests::test_css_module (src/bundler.rs:1904-2161); B8 when source-index plumbing changes.
- [MOD-12] (MAJOR) Renaming does not newly depend on `StyleSheet::minify`: a sheet printed without `minify()` (Rust callers; Turbopack dev mode before next.js#77313) hashes the same idents the same way as a minified one.
  verify: probe pairs with `mode: print` and `mode: minify` and `flags: css-modules` on the PR's inputs give the same hashed names (#935, #1118).
- [MOD-13] (MAJOR) New CSS-modules errors and warnings are deliberate: a warning promoted to an error is declared breaking, and new error kinds have stable names and messages (Turbopack maps error kinds to build severities).
  verify: read the src/error.rs diff; `css_modules_error_test` in the PR; warnings via `lcr show`, since deltas do not compare them (lib/lcr/adapter.py:114-122) (#842 made `@value` a hard error and broke pipelines; #865).
