# custom-properties checklist (VAR)
Covers `src/properties/custom.rs` (TokenList parse/print, `var()`, `env()`, color and `light-dark()` handling in token lists), `src/values/syntax.rs` and `src/rules/property.rs` (`@property`), the Unparsed paths of `src/properties/mod.rs`, `src/properties/prefix_handler.rs` (FallbackHandler) and `src/declaration.rs`. Spec: `references/spec/syntax-values.md` §5 (anchor keys in §0).
Top failure modes: token-list printing that merges tokens or drops whitespace (#976/#1201 fixed by 32f1f52, #1141, comments and `+` signs unfiled); handlers that reorder or delete declarations around `var()` (#1225, #805, #746, FallbackHandler); lowering inside custom properties that changes where values resolve (light-dark #821/#873, @supports copies #1381, `x` units #1286).
`[open #N]` / `master FAILS` marks a pre-existing bug: answer FAIL only if head is worse than base, extends it to new inputs, or claims the fix while the probe still fails.

- [VAR-01] (BLOCKER) Token-list whitespace that can matter after substitution is preserved: adjacent `var()`/`env()`/functions/idents/numbers keep one space when minifying, author whitespace is kept in non-minified output, and visitors still see whitespace tokens (#976, #1001, #1005, #1201, #646 fixed by 32f1f52 v1.31.0; PR #1029 rejected for re-deriving whitespace heuristically).
  verify: probes custom-properties/adjacent-var-whitespace-preserved, custom-properties/var-adjacent-whitespace, values-numeric/attr-ident-unit-space; O1 in Firefox (it rejects `12px0`-style substitutions); R2.
- [VAR-02] (BLOCKER) Every handler that buffers a property flushes before an `Unparsed`/`var()` declaration of the same or a related property, so source order survives in both directions, typed then var() and var() then typed (fixed: #805 22a8b6f, #504 da3aeb8, #187 957b1cd, #746 60622a1, 60b325b, 69ee0dd; master FAILS [open #1225]: src/properties/position.rs:104-114 has no Unparsed arm, src/declaration.rs:645-657 buffers direction/unicode-bidi; PrefixHandler updates in place, src/properties/prefix_handler.rs:24-46).
  verify: mutations var-before, var-after, reverse-decls; probes custom-properties/position-direction-var-fallback-order, display-layout/position-var-order, box-model-size/width-literal-then-var-order, rule-merging/prefix-handler-in-place-update-reorders-unparsed.
- [VAR-03] (BLOCKER) Dropping a comment or a sign never merges tokens in a token list (SYN#serialization): `12px/**/var(--f)`, `Arial/**/Black`, `1/**/2`, `x//**/*y` (would open a comment that eats the sheet), `1px+2px`, `1+2` and `2e3.4` keep a separator or the sign (master FAILS: `Token::Comment` prints nothing when minifying, src/properties/custom.rs:898-902, regression from 32f1f52; `has_sign` dropped at custom.rs:541-546).
  verify: probes printer-serialization/comment-dimension-function, custom-properties/comment-idents-custom-property, custom-properties/comment-removal-merges-custom-property-tokens, custom-properties/comment-removal-creates-comment-opener, custom-properties/plus-sign-token-boundary; R2.
- [VAR-04] (MAJOR) `light-dark()` lowering is not broadened beyond its documented limits: no `var()` toggles inside `@property initial-value` or other descriptors, the generated dark `@media` rule keeps `!important`, re-minifying does not repeat the toggles, and new behavior stays opt-out through `Features::LightDark` (by design [#821, #873]: custom properties resolve where declared, src/properties/custom.rs:1606-1617, src/properties/ui.rs:568-575; EM-08, arch-core N5, EM-132; open PRs #1287, #1383).
  verify: probes custom-properties/light-dark-not-lowered-in-property-initial-value, ui-misc/color-scheme-lowering-idempotent, color/light-dark-lowering-in-custom-property, color/light-dark-in-custom-property-inherited; dark-scheme oracle job (oracle.md L6); R2.
- [VAR-05] (MAJOR) Custom-property color fallbacks keep cascade semantics: the in-place fallback plus `@supports (color: …)` copies directly after the rule, with the same selector and `!important`, for every rule kind that holds declarations (style rules, nested declarations, `@starting-style`, keyframes, `@page`), and an author's own fallback pair is not overwritten ([open #1381]: src/rules/mod.rs:928-932 never drains side rules for NestedDeclarations, regression 6c465c1 v1.30.0, PR #1386; arch-core #1023 attaches them to the next sibling's selector; [open #109]).
  verify: probes custom-properties/nested-decls-custom-prop-supports-fallback, color/nested-decl-custom-prop-color-fallback, nesting/nested-declarations-side-rules-leak-to-sibling; mutations nest, important, wrap-supports; engine-legacy-2023; not testable with `attr_test` (StyleAttribute drops @supports side rules, src/context.rs:158-161).
- [VAR-06] (BLOCKER) An unparsed value without a valid substitution function (typo, future syntax, unsupported function) never deletes an earlier declaration of the same property; only valid `var()`/`env()`/`attr()` values are assumed valid, and only for targets with custom-property support (V5#resolve-property; master FAILS: FallbackHandler "Unparsed properties are always valid", src/properties/prefix_handler.rs:147-155, for color, fill, stroke, caret, caret-color, filter, backdrop-filter, text-shadow; PR #838 rejected for the same assumption; closed PR #1337).
  verify: probes rule-merging/invalid-color-does-not-override, rule-merging/invalid-color-replaces-valid, effects-masking/invalid-filter-empty-replaces-valid; O1; O7 `fallback-changed`.
- [VAR-07] (MAJOR) `@property` is accepted or rejected the way engines do: data type names are case-sensitive, unknown descriptors are ignored (rule kept), `initial-value` is parsed with the normal grammar (no unitless px; an unresolvable `color-mix(in srgb, currentColor 15%, transparent)` kept as tokens), and computational independence (`10em`, `var()`) is checked (PV#at-property-rule; master FAILS: src/values/syntax.rs:346 case-insensitive, src/rules/property.rs:198 rejects unknown descriptors, `initial-value:10` -> `10px`, [open #921]; history #654/#657, #968).
  verify: probes custom-properties/property-syntax-case-sensitive, custom-properties/property-unknown-descriptor, custom-properties/property-initial-value-unitless, custom-properties/property-initial-value-color-mix-currentcolor; O7 over css/css-properties-values-api.
- [VAR-08] (MAJOR) Unregistered custom property values keep the author's token text: no new color, number, unit, url or calc normalization in token lists, because `getPropertyValue`, `style()` queries and JS read the text (VAR#serializing-custom-props; master FAILS [#807 closed, #949 open]: src/properties/custom.rs:363-463 turns `#FF0000` into `red`, `1000ms` into `1s`, `1e3` into `1000`; abandoned PR #526 simplified var values; #1276 closed once its author saw custom-property calc() stays unreduced).
  verify: probes custom-properties/uuid-custom-property-verbatim, custom-properties/hex-color-custom-property-verbatim, custom-properties/custom-property-integer-precision, custom-properties/integer-token-keeps-all-digits; O1 (engines return the raw text, but number drift under 1e-4 relative and same-color spellings compare equal, so also use output-contains).
- [VAR-09] (MAJOR) Context-free rewrites in token lists are valid in every context the tokens can be substituted into: no unit or keyword lowering that is right for one property but wrong inside `image-set()` or another custom property (`x` -> `dppx`, regression dcbb9b8 v1.17.0 [open #1286], PR #1384; `--c:rgb(none 0 0)` -> `#000` drops the missing component).
  verify: probe gradient-image/image-set-x-unit-in-token-list; mutations retarget-legacy, retarget-modern; output-contains on the authored form.
- [VAR-10] (BLOCKER) `var()`/`env()` values parse as Unparsed in every property, including special-cased ones (`all`, shorthands), are kept as tokens in condition preludes that allow them (`@container` feature values, css-conditional-5, [open #1325]), and a syntactically invalid `var()` such as `var(--spacing(3))` fails only its own declaration (master FAILS [open #752; #1059 `all:vars` closed as invalid]: `all:var(--x)` is a stylesheet parse error since d7aeff3 v1.25.0, src/properties/mod.rs:714; #897 and #1100 by design).
