# perf checklist (PERF)

Covers speed, memory and size: `benches/transform.rs` + `benches/common/mod.rs` (CodSpeed via `.github/workflows/codspeed.yml`), `bench.js`, and perf-motivated changes in hot code (parsers with `try_parse` chains, `CssRuleList::minify`, the declaration handlers, `Printer::write_*`, napi conversion). config/areas.json maps only `benches/*` and `bench.js` to `perf`: apply this list too when a PR claims a speedup, a smaller binary or less memory, or has risk flag `core-file`.
Top failure modes: (1) work that grows exponentially or without bound with nesting (`try_parse` re-parsing #1098/#1382, unbounded recursion #910/#1092/#1297, output blow-up EM-112/EM-113); (2) optimizations that change output or determinism (stale cached keys #1235 and N1; #1263 restructured conditional-rule merging without new tests); (3) claims measured on the wrong path or not at all (CodSpeed and `lcr perf` time no-target minify only; type and binary size, #1332, #1305).
Evidence: P1/P2 come from the optional `lcr perf` stage (release CLI, median of 9 interleaved runs; P1 fails at total x1.1 with at least 60% of files >5% slower, P2 above +1%, config/checks.json); the adapter's 10 s per-request timeout (lib/lcr/adapter.py:20) turns a hang into an R1 failure; timing generators are in references/ecosystem.md §5.4.

- [PERF-01] (MAJOR) Work stays linear in nesting depth: no new recursive parse or print path without a depth bound, and no `try_parse` alternative that re-parses the same nested arguments once per alternative. Known: `parse_atan2` tries Length, Percentage, Angle, Time and Number in turn (src/values/calc.rs:816-845, O(5^depth)); nested math functions re-parse exponentially (#1098 open: nested `acos(((…` takes 8-9 s); TokenList tries `UnresolvedColor::parse` before the generic function path (src/properties/custom.rs:381, #1382 open, PR #1383); only TokenList has `MaximumNestingDepth` (depth > 500, src/properties/custom.rs:321-322, :369-370); selectors, calc sums and nested rules recurse unbounded (#1297, #1155, #910/#1092, PR #1245).
  verify: the references/ecosystem.md §5.4 generators at n=18 and n=22 on base and head (master, re-measured: unclosed `calc(100vh - `×18 0.19 s, ×22 2.3 s, and the CLI then aborts; roughly ×12-16 per +4 levels is the signal); probes calc-math/nested-sum-stack-overflow, calc-math/calc-repeated-clamp-no-overflow, nesting/host-amp-nested-rule-no-stack-overflow; R1; CALC-11, VAR-16, COLOR-24, SYN-05, PRINT-12.
- [PERF-02] (BLOCKER) Caches and hash-keyed indices added for speed stay consistent and deterministic: a key cached at insert is removed or recomputed when its rule is mutated or popped, `eq` never matches a slot against itself, and neither HashMap/HashSet iteration order nor the per-process `ahash` seed (`AHasher::default()` in `StyleRule::hash_key`, src/rules/style.rs:152-171) reaches output.
  verify: probes rule-merging/stale-dedupe-key-drops-rule-in-media, rule-merging/stale-dedupe-key-idempotent, rule-merging/stale-dedup-index-drops-nested-rule; run the corpus twice and compare deltas; R2; MERGE-07, GEN-12 (N1: `.a{color:red}.b{color:blue}.b{color:red}.b{color:green}` minifies to `.a,.b{color:red}`, verified on master; #1235 open, PR #1236; #855 d4eec35; #137).
- [PERF-03] (MAJOR) A change presented as performance-only is output-neutral: zero tuple, probe, mutation, WPT and real-world deltas and identical output on a second pass; every output change is listed and justified on its own.
  verify: delta counts per source in the `lcr review` log; S1; R2; O1 for any delta; probe rule-merging/adjacent-media-coalesce-important (#1263, 620a36b, replaced repeated merge-and-re-minify of adjacent conditional rules with one pass over the coalesced run and added no tests, so `!important` across the old rule boundary is covered only by this probe; #1305 c6ffd67 was a behavior-preserving refactor with no new tests).
- [PERF-04] (MINOR) Rule-list and declaration passes stay linear in the number of rules and declarations: no backward scan over `dest` or `rules` per item, no re-minification of an already minified list, no per-item rebuild of a collection.
  verify: read loops in the diff (nested iteration over `rules`, `decls`, `dest`, selector lists); CodSpeed `stylesheet/transform/conditional-run` in B6; P1; generator `.a{color-scheme:dark}`×2000 at chrome 80 (re-measured on master: 0.44 s, and 1.71 s at ×4000, so quadratic; EM-132) (#1263: re-minifying adjacent conditional rules was quadratic, x19 on the fixture; Devon on PR #1339: the backward scan "introduces quadratic behavior for consecutive declarations with distinct values", check `dest.last_mut()` instead; PR #1289 copied source content per mapping).
- [PERF-05] (MAJOR) Lowering and prefixing keep output size linear in input nesting: nested prefixed selectors are not re-printed once per ancestor prefix pass (`StyleRule::to_css` prints `to_css_base`, nested rules included, for every prefix, src/rules/style.rs:213-238; `:fullscreen{`×20 at safari 8 gives 357 MB, EM-112), and nested selector lists do not expand into cross products where `:is()` is available (`a,b{`×20 at chrome 100 gives 9.4 MB, EM-113).
  verify: the §5.4 generators at n=16 and n=20 on base and head (head output not larger); probe nesting/prefixed-nested-selector-no-duplication; NEST-12; S2.
- [PERF-06] (MINOR) Minified output does not grow on real-world CSS, and size trade-offs are declared: 32f1f52 keeps author whitespace in token lists for correctness, so `calc(var(--x) * 2)` no longer compacts (#1378, since v1.31.0); a merge whose result is longer than its input is a regression (#705, `transition` + `transition-property`).
  verify: S2 (fails above +0.1% of the minify-mode total); `lcr show` on each grown `r-*` case; MERGE-14; PRINT-04.
- [PERF-07] (MINOR) No new per-item allocation or hashing on the minify path: no `to_css_string()` per selector or declaration (PR #696 would serialize every selector of every rule on every minify), no `IndexSet`/`HashMap` where a `Vec` stack works (Devon on #878, adopted in 3ffe09e), expensive work only inside `or_insert_with` (Devon on PR #1237), early return when the targets need nothing (Devon on #182).
  verify: read the diff; risk flag `added-clone-heavy`; P1.
- [PERF-08] (MINOR) Printer hot paths do no extra per-call work: `write_str`, `write_char`, `whitespace`, `delim`, `newline` and `write_ident` gain no scanning, allocation, hashing or rare-case branch; rare cases get their own function, as `write_str_with_newlines` did for text with newlines (src/printer.rs:143-163; 0f064ab, Devon on #971: "write_str is very hot").
  verify: read the src/printer.rs diff; CodSpeed `stylesheet/transform/*` in B6; P1; PRINT-13, MAP-02.
- [PERF-09] (MINOR) Hot value types keep their size: rare or large variants stay boxed (`CssColor` boxes `LAB`, `Predefined`, `Float` and both `LightDark` arms, src/values/color.rs:58-66), and a PR that unboxes a variant or grows a common enum (`CssColor`, `Property`, `Length`, `Calc`) reports `std::mem::size_of` before and after plus a benchmark (Devon on PR #1332, which unboxes HSL/HWB: "It was originally boxed to reduce the size of CssColor since most of the time colors are 8-bit RGB.").
  verify: `size_of` printed on base and head (manual); CodSpeed in B6; P1; COLOR-25.
- [PERF-10] (MINOR) Release binary size grows by at most 1% and growth is explained: new dependencies, per-entry macro expansion (PROPS-13), code made generic per printer or per value type (PR #1289 made `ToCss` generic over the printer); cold paths can be `#[inline(never)]` as in c6ffd67 (#1305: -678 KB, about 14%).
  verify: P2 (`lcr perf`, `--features cli` release build); `cargo tree -e normal -p lightningcss` base vs head for new dependencies (manual) (#1322 thread: browserslist-rs 0.21 with deflate is about 2 MB smaller, and Devon weighed the oxc fork for size; #363 accepted growth for visitors).
- [PERF-11] (MINOR) Speed claims are measured on the path the PR changes, in release builds: CodSpeed times only `parse` and `parse + minify(default) + to_css(minify)` without targets (benches/common/mod.rs:31-46), and `lcr perf` only CLI `--minify --error-recovery` without targets (lib/lcr/perf.py:52-57), so lowering, source maps, CSS modules, bundling, `analyzeDependencies` and visitors need their own base/head timing.
  verify: P1; time the head and base release CLI with `--targets`, `--sourcemap` or `--css-modules`, or a node script, on the real-world files (manual) (Devon on #652: measure release builds).
- [PERF-12] (MINOR) JS bindings add no copy or crossing per call: results are built without an extra serde copy (25129b5 after #151), visitor hooks run only for node kinds the visitor declares (`visit_types()`; an all-hooks visitor costs about 2x no visitor, #363), and resolvers cross into JS once per import (#263 measured about 15% sync and 40% async resolver overhead).
  verify: VISIT-13; node timing of `transform` and `bundleAsync` on a large real-world file, base vs head, after `yarn build-release` (manual).
- [PERF-13] (MINOR) Benchmarks stay comparable across PRs: the fixtures `small`, `medium`, `large`, `conditional-run` and the groups `stylesheet/parse`, `stylesheet/transform` keep their inputs; a fixture for a new optimization lands before or apart from the optimization (#1271 0f44690 before #1263); `bench.js` methodology is the maintainer's call (#652: release build, one run per tool is deliberate).
  verify: diff benches/ and bench.js; B6 shows the CodSpeed check (codspeed.yml runs on every pull_request, but a first-time contributor's run waits for approval).
- [PERF-14] (MINOR) AST nodes gain no per-value storage: no stored locations, cached strings or owned copies of source text on value types (source ranges are recomputed on demand by `StyleRule::property_location`, #169), and parsers keep borrowing `CowArcStr` from the input instead of allocating `String`s.
  verify: read new struct fields and `to_owned()`/`to_string()` calls in the diff; risk flag `added-clone-heavy`; PERF-09.
