# Color checklist (`color`): `src/values/color.rs`, `src/values/alpha.rs` and the color fallback, `light-dark()` and `color-scheme` paths they drive (`prefix_handler.rs` FallbackHandler, `custom.rs` token-list colors, `context.rs` side rules, `ui.rs`).
Top failure modes: (1) panics when a fallback converts `currentcolor`/system colors; (2) author fallbacks, `@supports` copies or light-dark toggles silently dropped; (3) static `color-mix()`/relative-color evaluation or re-serialization that changes meaning (`none`, legacy vs non-legacy form, powerless rules, invalid input made valid).
Ordered by known incidents. Answer FAIL only when head introduces or extends a violation; one that base already has (master defects C1-C16 in `references/spec/color.md`, which also holds the INV-COLOR-* invariants) is PASS with the C-id and an unchanged case as evidence, and a PR that fixes one is credited. Probe ids are curated `corpus/probes/<area>/` ids.
