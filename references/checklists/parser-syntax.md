# parser-syntax checklist (SYN)
Covers `src/parser.rs` (TopLevelRuleParser, NestedRuleParser), `src/declaration.rs` (parse_declaration, DeclarationBlock::parse), `src/stylesheet.rs` (parse_with), `src/error.rs`, `src/values/ident.rs`, `derive/src/parse.rs`, the `Property::parse` fallback (`src/properties/mod.rs:700-726`) and cssparser bumps. Spec: `references/spec/syntax-values.md` §1 (anchor keys SYN, V4, V5, VAR, PV, OM, ENV in §0).
Top failure modes: errorRecovery deletes valid content or warns on valid input (#1358, #1137, #1370); valid CSS becomes a hard parse error (#752, #1303, #338); invalid input is accepted or repaired into valid output (#1199, `calc(1px + 1)`, `2e3.4`).
`[open #N]` / `master FAILS` marks a pre-existing bug: answer FAIL only if head is worse than base, extends it to new inputs, or claims the fix while the probe still fails.

- [SYN-01] (BLOCKER) With errorRecovery, an invalid declaration, invalid nested rule or disallowed at-rule removes only itself; every valid declaration before and after it in the same block survives (SYN#consume-block-contents; master FAILS [open #1358]: `declarations.clear()` at src/parser.rs:496-498 since a8b7ea0 v1.22.0; fix PR #1374).
  verify: probes parser-syntax/error-recovery-keeps-earlier, parser-syntax/error-recovery-keeps-earlier-declarations, parser-syntax/error-recovery-keeps-decls-before-at-rule, parser-syntax/error-recovery-keeps-decls-before-star-hack, nesting/error-recovery-keeps-declarations-before-invalid-nested-rule (flags error-recovery); O1; `error_recovery_test` warnings asserted in the PR.
- [SYN-02] (BLOCKER) No valid CSS becomes a stylesheet-level parse error: every typed or special-cased property keeps the `Property::Unparsed` fallback for `var()`/`env()`/unknown values (src/properties/mod.rs:719-724), and a new grammar branch falls back to tokens instead of returning Err (regressions: `all:var(--x)` d7aeff3 v1.25.0 [open #752]; `::search-text:current` e013c45 [open #1303]; `@property` inside `@layer` #968 fixed by #1090; master FAILS for url() modifiers and `@property --a, --b`).
  verify: probes custom-properties/all-var-accepted, gradient-image/url-request-modifier; mutations var-before, var-after (a head-only request error is a delta); `lcr show` on cases that error only on head.
- [SYN-03] (MAJOR) errorRecovery changes nothing for valid input: base and head give identical output and an empty warnings list for valid CSS, and every new branch keyed on `Err` is also tested with errorRecovery on, where errors become `Unknown` (#1137 regression 220b390, fixed f3666d6; [open #1370], PR #1379; #954 shipped `dbg!()`).
  verify: probes supports-container/container-name-only-error-recovery, media-queries/general-enclosed-calc-error-recovery; re-run the PR's valid test inputs with flags error-recovery; grep the diff for `dbg!`, `println!`, `eprintln!`.
- [SYN-04] (MAJOR) Browser-invalid input stays invalid: the PR adds no leniency (quirky unitless lengths, hashless hex, `//` comments, IE `*`/`_` hacks, numbers glued to idents such as `2n+1of`), and no typed parser accepts a value its grammar rejects, which would let dedupe delete the author's earlier valid declaration (master FAILS [open #1199/#682]; `calc(1px + 1)` pinned at src/lib.rs:8538; rejected PRs #1240, #986; #1273 is a correct rejection).
  verify: O7 `invalid-became-valid` for css/css-syntax and css/css-values; probes values-numeric/unitless-length-invalid, calc-math/unitless-zero-in-calc-keeps-fallback, selectors/nth-child-of-requires-whitespace; a probe with the invalid form after a valid one (`expect: equivalent`).
- [SYN-05] (BLOCKER) No new panic, stack overflow or super-linear parse time: every new recursive path, and every `try_parse` alternative inside a recursive grammar, is depth-bounded or linear (only TokenList has `MaximumNestingDepth`, src/properties/custom.rs:322, :370; open #1297 selectors and nesting, #1098 `atan2` O(5^depth), #1382 nested `light-dark()`, #910 calc; unclosed nested `calc(` ~x10 per 4 levels, EM-26).
  verify: R1 (panics, aborts, timeouts); probes calc-math/sum-of-parenthesized-sums-no-crash, nesting/host-amp-nested-rule-no-stack-overflow; generated depth-18 and depth-22 probes (`expect: no-panic`) on base and head, where cost growing x16 per 4 levels is the signal.
- [SYN-06] (MAJOR) Nested and secondary parsers inherit the caller's ParserOptions (error_recovery, warnings, flags, css_modules, source location): no new `ParserOptions::default()`, `filter_map(Result::ok)` over rule results, or fresh `ParserInput` over a substring without a token-list fallback ([open #1103] src/rules/keyframes.rs:403-415, src/parser.rs:879-889; `@font-face` descriptors src/parser.rs:798-808; [open #921] src/rules/property.rs:89-100).
  verify: grep the diff for `ParserOptions::default()`, `filter_map(Result::ok)`, `ParserInput::new(`; probes transition-animation/keyframe-nested-at-rule, custom-properties/property-initial-value-color-mix-currentcolor.
- [SYN-07] (MAJOR) Dependency and tokenizer upgrades (cssparser and its `Token` fields) keep output identical or explain every delta: each hand-built `Token` passed to a cssparser serializer sets `int_value` and `has_sign` correctly (#1200 cssparser 0.37: `10%` printed as `0%` until fixed in the PR, and integral dimensions now saturate at i32, see NUM-04).
  verify: B4; tuple and realworld deltas (S1); probes values-numeric/percentage-int-value-serialization, values-numeric/large-integral-value-no-i32-saturation.
- [SYN-08] (MAJOR) A strictness change (error, warning, accepted) matches what browsers do with that input (`CSS.supports`, dropped rule), keeps errorRecovery dropping exactly what browsers drop, and is called out as breaking when a warning becomes an error (#842 `@value`; by design: #39, #412, #897 and #1100 invalid `var()`).
  verify: O3 (declarations or rules an engine rejects); probe custom-properties/invalid-var-dropped-with-recovery; the PR's error_test / error_recovery_test cases.
- [SYN-09] (MAJOR) A new or reordered variant in a `#[derive(Parse)]` enum or `enum_property!` keeps parse priority: unit variants match as idents, data variants are tried in declaration order and the last variant's error propagates (derive/src/parse.rs:44-178), so a broad variant placed first never shadows a narrower one or swallows a keyword.
  verify: read the enum diff; a probe per affected keyword and per data variant (`output-equals` when the spec fixes the form); T2.
- [SYN-10] (MAJOR) Case rules follow the spec: property, at-rule and function names and keywords are ASCII case-insensitive, while `--*` names, `<custom-ident>`s, env() names and `@property` data type names are case-sensitive; `eq_ignore_ascii_case`/`match_ignore_ascii_case!` is used only for the former (master FAILS for env() names, VAR-15, and `"<LENGTH>"`, VAR-07).
  verify: mutation upper-props; probes custom-properties/custom-property-name-case, custom-properties/env-name-case-sensitive, custom-properties/property-syntax-case-sensitive.
- [SYN-11] (MAJOR) Decoding is unchanged unless intended: a leading UTF-8 BOM is handled the same at file level and in bundles (never kept inside a selector), `@charset` handling (src/parser.rs:340-345, always dropped) is preserved, and tests assert bytes, not inline `<style>` rendering ([open #338], PR #1301; INV-SYN-010).
  verify: output-contains / output-not-contains probes (the oracle cannot see U+FEFF in inline styles); bundler tests in src/bundler.rs; `lcr show`.
- [SYN-12] (MAJOR) `unicode-range` parsing round-trips valid ranges exactly (`?` wildcards, the U+10FFFF boundary, lowercase `u+`), and a list with an invalid range keeps the whole descriptor invalid (INV-SYN-011; src/rules/font_face.rs:311-321).
  verify: probe font/sft-font-face-unicode-range-compression; test_font_face tuples (T4); R2.
- [SYN-13] (MAJOR) `!important` follows SYN#consume-declaration: `!` plus ASCII case-insensitive `important` as the last two non-whitespace tokens, whitespace and comments between allowed, nothing after; importance never moves between the normal and important declaration lists (INV-SYN-003).
  verify: probe parser-syntax/important-whitespace-case; mutation important.
- [SYN-14] (MAJOR) `{}` in values: custom properties keep blocks verbatim, a non-custom value with a top-level `{}` plus other tokens stays invalid and is never reparsed as a nested rule, and `--foo:hover{}` stays a declaration (INV-SYN-006; csswg #9317, #9336).
  verify: write a probe with `--x:{a} b` next to `width:10px {}` (flags error-recovery; on master SYN-01 also deletes `--x`); SYN#consume-declaration.
- [SYN-15] (MINOR) Source locations and warning positions point at the token after skipped whitespace and stay relative to the original file for re-parsed substrings ([open #1149] src/values/url.rs:33-37, PR #1150; #921 loses the location).
  verify: PR tests asserting `loc`/line/column; node/test location tests (B5).
- [SYN-16] (MINOR) CDO/CDC are dropped only at the stylesheet top level and kept inside blocks and custom properties (INV-SYN-005); a block left open at EOF nests every later rule, which is spec behavior (#1345: its repro input has 701 `{` and 699 `}`), and adding a warning for it changes no output.
  verify: probe parser-syntax/cdo-cdc-top-level; `lcr show` of a probe with an unclosed block.
