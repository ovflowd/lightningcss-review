# prefixing-compat checklist (COMPAT)

Covers vendor prefixes and target decisions: `src/properties/prefix_handler.rs` (PrefixHandler, FallbackHandler), `src/targets.rs` (`Targets`, `Features`, `should_compile*`, `prefixes()`), `src/vendor_prefix.rs`, the generated `src/compat.rs`, `src/prefixes.rs`, `node/flags.js`, `node/targets.d.ts`, their generator `scripts/build-prefixes.js` with the data pinned in yarn.lock, and `node/browserslistToTargets.js`.
Top failure modes: (1) an author-written prefixed/unprefixed pair is overwritten, dropped or duplicated (#695 family, FallbackHandler since 2694a18, v1.21.0); (2) compat data counts partial, prefixed or mobile-only support as full support (#1283, #508, Opera Android numbering); (3) a lowering emits syntax or legacy semantics the targets cannot use (#1361, #936/#1107, image-set strings).
Many items name open master bugs: answer FAIL only when head is worse than base (transition `regressed`) or a claimed fix is incomplete, and credit fixes via A2. Probes cannot set include/exclude or `targets: {}`; use the PR's Rust or node tests (tuples keep include/exclude).

- [COMPAT-01] (BLOCKER) Author-written prefixed/unprefixed pairs are not newly overwritten, dropped or merged: in both source orders, with and without targets, every declaration a target or a current engine needs survives with its own value (FallbackHandler overwrites the stored slot including its prefix, prefix_handler.rs:116-121 and :148-151; PrefixHandler merges on an equal value or overlapping prefix, :30-34).
  verify: mutations `prefixed-sibling`, `reverse-decls`, `retarget-none`; probes prefixing-compat/issues-important-backdrop-filter-standard-then-webkit, prefixing-compat/issues-b1-unprefixed-backdrop-filter-dropped, prefixing-compat/issues-important-backdrop-filter-webkit-kept-for-safari, effects-masking/issues-b5-backdrop-filter-unprefixed-kept; O1, O3 (#695 #1086 #1229 #1327 #537 #977).
- [COMPAT-02] (MAJOR) Prefix generation is idempotent and duplicate-free: minifying the output again adds no second copy of a prefixed declaration, `@supports` operand or `transition-property` entry, including `var()` and CSS-wide-keyword values that take the Unparsed `get_prefixed()` path (text.rs:1196, masking.rs:700-707).
  verify: R2 on every delta; probes text/issues-important-text-decoration-prefixed-inherit-idempotent, prefixing-compat/issues-b1-mask-image-var-duplicate; mutation `var-after` with `retarget-legacy` (#403 #872 #969 #478; #436 open: `image-set()` printed twice for ancient targets; open PRs #1295 #1334 #1339).
- [COMPAT-03] (MAJOR) A BCD-derived compat key the PR adds or re-sources ignores `partial_implementation`, `prefix`, `alternative_name` and `flags` entries unless the lowering emits exactly that form, and the picked entry's `notes` were read; today only `mediaIntervalSyntax` and `statePseudoClass` filter partial entries (build-prefixes.js:266-278, :347-360; picker :433-437).
  verify: read the build-prefixes.js diff against `@mdn/browser-compat-data` at the yarn.lock version; probes transition-animation/issues-b5-animation-timeline-not-folded-chrome-115, gradient-image/sie-image-set-type-fallback-kept, color/spec-color-lowering-rec2020-needs-fallback-for-safari14 (#1283 #1342 #1115; Devon on #1306: "partial support should not imply full support").
- [COMPAT-04] (MAJOR) Compat changes are made in `scripts/build-prefixes.js` or the pinned data packages, never by hand: regenerating reproduces the committed `src/compat.rs`, `src/prefixes.rs`, the `Browsers`/`Features` blocks of `src/targets.rs`, `node/flags.js` and `node/targets.d.ts`, and every hard-coded override carries a comment with its bug link.
  verify: B11 (runs when these files, the script, package.json or yarn.lock change); the `generated-edited` risk flag is advisory and B11 decides (#564 #1178 #1284).
- [COMPAT-05] (MAJOR) A compat-data refresh or source swap comes with a per-browser decision diff, not only for the browser in the bug: thresholds that moved down (unsafe), prefix ranges closed at the snapshot's newest version, keys that lost a browser, and overrides that no longer match the data.
  verify: run `node scripts/build-prefixes.js` in base and head with their own lockfiles and diff the generated tables per feature and browser; S1 on realworld `lower-*` cases; probe selectors/browser-compat-marker-list-not-split-safari (#325 and #925 closed ranges; the #508 `::marker` override is dead with the pinned caniuse-lite data, verified on master: `safari 18` splits `.t, .t::marker`; #1198 moved ios_saf, opera, samsung and android thresholds).
- [COMPAT-06] (BLOCKER) Legacy prefixed syntax keeps its legacy semantics through every later stage (compact printer, merging): `-webkit-linear-gradient` keywords name the start side and angles are polar (0deg points east), 2009 `-webkit-box-ordinal-group` is `order + 1` and at least 1, `-webkit-mask-composite` keeps its own keywords, legacy placeholder pseudos keep their names.
  verify: PR lowering tests also in compact mode (`minify_test_with_options_and_browsers`); probes gradient-image/issues-b3-prefixed-gradient-minify, gradient-image/community-prs-prefixed-gradient-default-direction-minify, flex-grid-align/browser-compat-box-ordinal-group-offset-by-one; O4 with `engine-legacy-*` (gradient.rs:268-300 and :501-542, flex.rs:353-358; #918 #936 #1107).
- [COMPAT-07] (MAJOR) Every construct a lowering introduces is itself supported by the same targets: `not (…)`/`or` media (boolean MQ4 syntax shipped together with range syntax), the `:is()` that nesting lowering writes, string URLs inside unprefixed `image-set()` (Safari 10.1-13.1 accept only `url()`), `at <position>` inside `-webkit-radial-gradient()`.
  verify: O3 and O4 with `engine-legacy-2021`/`engine-legacy-2023`; probes media-queries/issues-b5-range-lowering-mq3-compatible, gradient-image/browser-compat-image-set-url-kept-for-safari-13, gradient-image/browser-compat-webkit-radial-gradient-legacy-position (#1361 since 7f29035, #1159, image.rs:453-468, gradient.rs:368-415).
- [COMPAT-08] (MAJOR) Fallback pruning is target-aware: an earlier declaration is dropped only when every target supports the later value, so `IsCompatible` checks every value inside it (no stub `true`, effects.rs:410), and authored fallback pairs (`color:#x; color:lab()`, `url()` before `image-set()`, `-webkit-fill-available` before `stretch`, `overflow:hidden` before `clip`) survive when a target needs the first.
  verify: probes prefixing-compat/issues-b5-overflow-clip-author-fallback-kept, effects-masking/pr1364-filter-fallback-kept, gradient-image/sie-image-set-type-fallback-kept; mutation `retarget-legacy`; O4 (#252 #1360 #109 #826 #1319).
- [COMPAT-09] (MAJOR) The three target modes stay distinct and unchanged: no targets (nothing lowered, authored prefixes kept: `is_compatible` is true, targets.rs:226-228), `targets: {}` (every feature compatible so nothing is lowered, but `prefixes_for` returns only `None`, so authored prefixes are stripped, and selector-list compat checks run, targets.rs:238-253), and real targets; a change to no-targets output has the maintainer's sign-off.
  verify: mutations `retarget-none`, `retarget-modern`, `retarget-legacy`; `{}` is `Browsers::default()` in a prefix_test or `targets: {}` in a node test (probes cannot express it); verified on master: generated `is_compatible` returns true when no browser is set (src/compat.rs:237-), so `{}` does not mean "maximal lowering" (#826, PR #1350, vite#23294, astro#17647).
- [COMPAT-10] (MAJOR) Every emitted prefixed name or value exists in the engines it targets: each new prefixed form is checked against BCD (`alternative_name`, `prefix`) and autoprefixer's `lib/hacks/*` renames, not taken from autoprefixer's prefix list alone.
  verify: probes prefixing-compat/issues-b3-print-color-adjust-firefox, prefixing-compat/community-prs-print-color-adjust-no-moz-prefix; O3 in legacy engines (#1102 emits `-moz-print-color-adjust`, which never existed: Firefox 48-96 used `color-adjust`; #511 `::-webkit-backdrop`; #492).
- [COMPAT-11] (MAJOR) Each `Features` flag gates only its own transform: checks call `should_compile(feature, flag)` with that flag, never `intersects()` on a group mask (`should_compile_selectors`, targets.rs:238-241, turns off all selector work when any selector flag is excluded), and lowering with a single flag included (e.g. `MediaRangeSyntax` without `MediaIntervalSyntax`) still emits valid output.
  verify: PR tests via `nesting_test_with_targets`/`test_with_printer_options` with `Targets { include, exclude }` or node `transform({include, exclude})`; probe media-queries/issues-b3-range-lowering-parens (#1375; #1105 fixed by #1114; Tailwind excludes LogicalProperties, DirSelector and LightDark).
- [COMPAT-12] (BLOCKER) Printers handle every prefix bit that `targets.prefixes()` can return: `include: Features.VendorPrefixes` yields `VendorPrefix::all()` (targets.rs:245-246), so no `match` on a prefix may reach `unreachable!()` (Size/MaxSize `Stretch` at size.rs:120-124 and :253-257 do today).
  verify: R1 on a PR or node test with `include: VendorPrefixes`; risk flag `added-panic`; grep the diff for matches on `VendorPrefix` (#1371 open, PR #1377).
- [COMPAT-13] (BLOCKER) `@supports` conditions keep the author's prefixes and operators: no prefixed operand becomes unprefixed, `and` never prints as `or`, and no prefix expansion happens inside `not (…)` (same-property operands are merged under a prefix-less key, supports.rs:225-252, since 6bd2761).
  verify: probes supports-container/issues-important-supports-prefixed-operand-unprefixed, supports-container/arch-core-supports-and-prefixed-stays-and, supports-container/asr-supports-and-prefixed-pair; O3, since `CSS.supports()` differs (#710 open, `and` → `or` unfiled and verified on master, #977; PRs #1313/#1316).
- [COMPAT-14] (MAJOR) Handlers that clear or regenerate legacy longhands keep the authored legacy declarations that the standard property does not replace: with targets, `flex-direction` does not erase a `-webkit-box-orient` used by the `-webkit-line-clamp` idiom (flex.rs:530-553), and an earlier `display:flex` survives a later prefixed `display` value (display.rs:380-392).
  verify: probes flex-grid-align/arch-props-values-webkit-box-orient-dropped-with-flex-direction, flex-grid-align/issues-b5-display-flex-before-ms-flexbox; mutation `prefixed-sibling` (#1291, PR #1385).
- [COMPAT-15] (MAJOR) Vendor alias tables round-trip: the parse and print mappings of prefixed pseudo-classes and pseudo-elements are inverses (input equals output when nothing is lowered), a legacy name maps only to a feature with the same semantics, and no lowering adds an unprefixed copy that turns a dead selector live.
  verify: probes selectors/issues-b5-legacy-ms-input-placeholder, selectors/asr-ms-input-placeholder-preserved, selectors/pr1352-ms-input-placeholder-stays-inert, selectors/prefixed-any-inside-not-preserved-without-targets; `print` mode round trip (#929 → #1351: `:-moz-placeholder`/`:-ms-input-placeholder` parse as PlaceholderShown, selector.rs:168-169; `::-ms-input-placeholder` stored as Moz, :291; #1211 open: with modern targets the `:-webkit-any(:lang())`/`:-moz-any(:lang())` rules are dropped as duplicates of `:is()`; separately, verified on master, with no targets `.a:not(:-webkit-any(.b,.c))` prints `.a:not(:is(.b, .c))`, because `get_prefix` does not look inside `:not()`, selector.rs:2075-2100).
- [COMPAT-16] (MAJOR) JS `browserslistToTargets` and Rust `Browsers::from_browserslist` give the same targets for the same query: mobile keys (`and_chr`, `and_ff`, `op_mob`) are mapped with the minimum version kept, unknown keys are mapped or rejected, and a browserslist-rs bump comes with a resolved-targets diff.

- [COMPAT-17] (MAJOR) Desktop and mobile data stay apart where the PR touches the mapping: no BCD-derived `opera` threshold falls below desktop Opera's value (`opera_android` overwrites `opera`, build-prefixes.js:449-450; verified on master: `lab()` gets no fallback for `opera 90` but does for `chrome 104`), and caniuse-only data is not trusted for `android` 5 to latest-1 (caniuse folds WebView into 2.1-4.4.4 plus latest).
  verify: probes prefixing-compat/arch-core-opera-desktop-lab-fallback, prefixing-compat/browser-compat-opera-desktop-media-range-lowered, prefixing-compat/browser-compat-android-webview-mask-prefix, box-model-size/browser-compat-opera-desktop-dvh-fallback-kept, prefixing-compat/issues-b0-text-size-adjust-webkit-ios (master fails them: credit fixes, do not count failures) (#1180 fixed only `#rrggbbaa` via #1198; #934 open: `text-size-adjust` needs `-webkit-` only for ios_saf, so a desktop-Safari target list strips the authored prefix that iOS needs).
