# bindings-api checklist (API)

Covers the public surfaces: napi (`napi/src/lib.rs` Config, BundleConfig, AttrConfig; `napi/src/transformer.rs`), `node/` (index.js loader, hand-written index.d.ts, generated ast.d.ts, targets.d.ts and flags.js, browserslistToTargets.js), `wasm/`, the C bindings (`c/src/lib.rs`, cbindgen `c/lightningcss.h`), the CLI (`src/main.rs`), `src/error.rs`, `src/stylesheet.rs`, `derive/`, `static-self*`, `examples/`, and serde shapes.
Top failure modes: (1) TS and AST types drift from the runtime (#739/#796 options without types, #524 invalid TS, #1147 `Rotate`, #1261); (2) Rust API and semver breaks (#784 parcel_selectors variant, #739 broke the C crate, #880, #1139); (3) feature- or target-gated code that CI never builds (#1251, #1094, wasm fixes 362bce5/5a145da, the C crate).
Downstream code depends on contracts LightningCSS's tests do not pin (references/ecosystem.md): warning text and error kinds, `Features` bits, `targets: {}` vs undefined, placeholder format, export order, the native loader.

- [API-01] (MAJOR) `node/index.d.ts` (hand-written) matches `napi/src/lib.rs` for every added or renamed option and result field: same camelCase key, optionality matching `#[serde(default)]`/`Option`, result shapes (`dependencies`, `exports`, `warnings`, resolver `string | {external}`) and doc comments; `yarn tsc` passes and `scripts/build-flow.js` still converts the file.
  verify: B5 (`yarn build` runs build-flow.js; `yarn tsc` checks node/*.d.ts for validity only, not against Rust, so compare napi/src/lib.rs:563-678 with node/index.d.ts by reading) (#739/#796 typed later in eb49015; #524 → #528; #1261; Flow limits in #91/#204).
- [API-02] (MAJOR) New napi options are optional and default to current behavior (`#[serde(default)]`, or `Option` with `unwrap_or(current)`), and existing options keep their meaning.
  verify: a node test without the new option gives the base output; B5 (#290: a required field broke `transformStyleAttribute`, 676bf1f → 83fd8a7; #739, Devon in review: "These should probably default to true like below.", napi/src/lib.rs:731-734 and :862-865; #1158).
- [API-03] (MAJOR) `node/ast.d.ts` matches the runtime AST: it is regenerated with `yarn build-ast` when serde-visible types change, the index-based untagged-variant patches in scripts/build-ast.js:60-98 (Translate, Scale, AnimationAttachmentRange, NoneOrCustomIdentList, ViewTransitionGroup `types[3]`, ViewTransitionName `types[2]`) are updated when such an enum gains a variant, and a visitor dump of a changed node matches its declared type.
  verify: B11 (its AST lane runs only with risk flag `public-api` or `ast-types-changed`, otherwise run `yarn build-ast` by hand); compare with base's regeneration, because master already drifts: node/ast.d.ts:6509-6510 lacks `"match-element"` that src/properties/transition.rs:129 has since 2b7f9e9 (verified by reading) (#1147, #1274 latent and UNVERIFIED, #703).
- [API-04] (MAJOR) Rust public API changes are listed in the PR: new variants on public enums (`ParserError`, `MinifyErrorKind`, `PrinterErrorKind`, `CssRule`, `Property`, `parcel_selectors::SelectorParseErrorKind`), new public struct fields (`css_modules::Config`, `ParserOptions`, `PrinterOptions`, `Targets`), changed trait signatures (`SourceProvider::resolve`, `Visitor`, `AtRuleParser`, `ToCss`) and changed payload types (FamilyName became a newtype with a private field, #1139).
  verify: risk flag `public-api`; read the diff (#784: `cargo install trunk` failed with E0004 because parcel_selectors is a caret dependency, Cargo.toml:67; #880; #406; #574).
- [API-05] (MAJOR) Every workspace member that uses a changed public type still builds: the C bindings build `css_modules::Config` and options by struct literal (`..Default::default()`, c/src/lib.rs:286-290) and `c/lightningcss.h` equals cbindgen's output; napi, the CLI and the examples compile.
  verify: B10 (runs only when `c/` changed: build `-p lightningcss_c_bindings` by hand when a public struct used by c/src/lib.rs changes; #739 broke it from 1.25.0 to 1.27.0); B1 (examples and CLI tests under --all-features).
- [API-06] (MAJOR) Feature- and target-gated code compiles in each documented combination: every serde, schemars, visitor and into_owned attribute sits behind `cfg_attr(feature = …)`, dependency features are gated by the crate's own features (indexmap's `serde` is unconditional, Cargo.toml:78, #1094 open), and `cfg(target_arch = "wasm32")` code compiles.
  verify: B8 (lib with all optional features off, so bundler-only code is skipped) and B9 (check only, no link); also `cargo check -p lightningcss --no-default-features --features bundler,sourcemap` (the #1251 combination) and `--features serde`, `visitor`, `into_owned` one at a time (48841f7, #360, 362bce5, 5a145da).
- [API-07] (MAJOR) The minify/print split is unchanged: what Rust callers get only from `StyleSheet::minify` (prefixes, light-dark toggles, unparsed animation-name scoping) and what happens at print time (nesting, media ranges, `#rrggbbaa`, `clamp()`, `light-dark()` in token lists) stay where they are, and JS `minify: false` still runs `StyleSheet::minify` (napi/src/lib.rs:761, :896, :1019; CLI src/main.rs:208-213).
  verify: probe pairs in `print` and `minify` modes on the PR's inputs; read where the transform lives (#1118, #882, #935, #1158).
- [API-08] (MAJOR) Error and warning surfaces stay stable: serde `type` names, messages, `data` payloads and locations are unchanged unless declared, Rust `ErrorLocation.line` stays 0-based and `column` 1-based while JS `loc` is 1-based for both, and promoting a warning to an error is declared breaking.
  verify: diff src/error.rs; node tests asserting error objects; warnings are returned by the adapter but not compared in deltas (lib/lcr/adapter.py:114-122), so compare them with `lcr show` (Tailwind regex-filters warning text; Turbopack fails builds on `EndOfInput`, next.js#98261 via #1370; Vite subtracts 1 from the column; Parcel reads `err.data.type`; #813; #842).
- [API-09] (MAJOR) New or changed CLI paths report errors with a message and a non-zero exit and add no `unwrap()`/`expect()` on user input (existing unwraps at src/main.rs:189-223 cause #1317, an abort on invalid CSS (closed as stale, still aborts on master), and #1320, a panic on Baseline queries; PR #1315).
  verify: risk flag `added-unwrap` on src/main.rs; run the head CLI on an invalid file and on `--targets 'baseline widely available'` (the harness does not run the CLI outside its integration tests).
- [API-10] (MAJOR) CLI flags mirror the JS options they claim to mirror and keep the conventions: `--no-x` names for negations (#324), opt-in config discovery (`--browserslist`), JSON output with `code` and `exports` when no output file is given (#192, a5fdcc1), and an integration test for the new flag.
  verify: tests/cli_integration_tests.rs (`required-features = ["cli"]`, built by B1's --all-features); website/pages/docs.md "From the CLI" (the CLI cannot set include/exclude, the deep combinator, unusedSymbols, pseudoClasses or inputSourceMap: src/main.rs:22-66, #1230).
- [API-11] (MAJOR) The native loader stays statically analyzable and compatible: platform package names `lightningcss-<platform>-<arch>[-<abi>]` (node/index.js:1-21), no `require()` of a path missing from the package, the first `require` error is not hidden behind a misleading second one, and the export shape that Tailwind patches still applies.
  verify: diff node/index.js; B5 (`yarn test` loads the binary) (#701; #931/#955, the `require('../pkg')` branch removed in #1170; #920/#1269; Tailwind ships patches/lightningcss@1.33.0.patch against this file).
- [API-12] (MAJOR) wasm stays in parity: the `wasm/` entry points mirror node (`init()`, index.mjs, wasm-node.mjs), wasm-only code (napi/src/lib.rs:421-422 `mod bundle`, node/src/lib.rs:42 and :55) compiles, and a change to the wasm import set (getrandom's `__getrandom_v03_custom`, napi-wasm) updates the shipped loaders in the same PR.
  verify: B9 is a compile gate: link errors such as `rust-lld: undefined symbol: napi_*` need `yarn wasm:build-release`, i.e. CI test-wasm (B6) (#1022/#1077, #672, #394, #643, 362bce5, 5a145da).
- [API-13] (MAJOR) Public serde shapes are stable JSON contracts: `Targets` (serde since #1015; Turbopack relies on it), `Dependency` (`type`, `placeholder`, `loc`), `CssModuleExport`, warning objects; renamed fields or new required fields are breaking, and returned collections keep source order (IndexMap, #1355).
  verify: tests/test_serde.rs (`--features serde`, under B1); node tests asserting result objects.
- [API-14] (MAJOR) Strings cross the JS boundary losslessly: filenames with NUL (`\0` virtual module ids from Vite and Rollup), lone surrogates and non-ASCII text round-trip through `filename`, source-map `sources` and CSS-module hashes.
  verify: node test with `filename: '\0virtual.css'` that checks the map's `sources`; B5 (#874: napi 2.15 truncated at NUL, fixed by the 43707c3 bump).
- [API-15] (MAJOR) Async and threaded entry points cannot panic or deadlock: `bundleAsync`, JS resolvers called through threadsafe functions and rayon workers return errors (release `panic = 'abort'` aborts Node), and options shared by `transform`, `transformStyleAttribute`, `bundle` and `bundleAsync` behave the same in each.
  verify: node bundle.test.mjs async tests run repeatedly; R1 (#1164 random crash on Windows, open; #263 "Fix race").
- [API-16] (MINOR) `browserslistToTargets` and `Browsers::from_browserslist[_with_config]` keep their contracts: mobile and unknown keys are mapped or rejected rather than silently ignored, and the re-exported `BrowserslistConfig` (browserslist-rs `Opts`, #1011) is treated as API.
  verify: node test `browserslistToTargets(['and_chr 120', 'op_mob 80'])`; COMPAT-16 (#1088 open).
