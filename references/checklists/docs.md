# docs checklist (DOCS)

Covers user documentation: `website/pages/*.md` (docs, transpilation, minification, css-modules, bundling, transforms), `website/*.html` + `website/include/layout.html` (page stubs, navigation), `website/playground/{index.html,playground.js}`, `README.md` (also shipped as wasm/README.md), `CONTRIBUTING.md`, rustdoc (`#![deny(missing_docs)]`, docs.rs) and the doc comments in `node/index.d.ts`.
Top failure modes: (1) examples that do not run or show output the code does not produce (#473, #431, #894, #798, #964, #1005; matrix examples since #288); (2) options and hand-maintained lists that lag the code (#739/#796 shipped options whose TS types came only in eb49015; five options undocumented today, DOCS-02); (3) broken links and site builds (#33, #584, #750, #823, #285, #741).
No CI job builds the website or checks docs, and the oracle never reads them: the evidence is reading, grep and PR probes made from doc examples (`lcr show <run> p-…`). Known master mismatches are listed in DOCS-04; credit fixes, do not count them against the PR.

- [DOCS-01] (MINOR) Every code example the PR adds or edits runs as written on head: JS snippets import what they use (`browserslistToTargets`, #798) and use option keys that exist in node/index.d.ts, CSS snippets parse, and each shown result ("compiles to", "minifies to", "is equivalent to") is head's output for the stated options and targets, modulo whitespace.
  verify: one PR probe per changed CSS example with the example's mode and targets, read with `lcr show <run> p-…` against the docs block; JS snippets run with node after `yarn build` (manual) (#473 transforms example, #431 Deno example, #894 `color()` output, #726 Windows CLI example).
- [DOCS-02] (MINOR) A new or renamed user-facing option is documented on the page that owns it with its JS key, CLI flag and default: docs.md (basics, error recovery, source maps, CLI), transpilation.md (targets, include/exclude, drafts, pseudoClasses, nonStandard), minification.md (unusedSymbols), css-modules.md (`cssModules.*`), bundling.md (resolver), transforms.md (visitor, customAtRules), and the node/index.d.ts doc comment says the same.
  verify: grep website/pages/*.md and README.md for the key; API-01; GEN-25. Undocumented on master (verified by grep, not the PR's debt): `drafts.scrollNavigationControls` (#1185, playground only), `analyzeDependencies.preserveImports`, `transformStyleAttribute()`, `cssModules.container` (#835), CLI `-d/--output-dir`.
- [DOCS-03] (MINOR) Links and anchors resolve: markdown-it-anchor slugs every heading, so a renamed heading breaks in-page links (`#%3Alang()-selector` and `#%3Ais()-selector`, transpilation.md:430, :450) and cross-page links (`css-modules.html#dependencies`, bundling.md:38); external links (MDN, drafts.csswg.org anchors, npm, unpkg, GitHub) resolve.
  verify: grep website/pages, README.md and node/*.d.ts for the old slug; open each changed external link (manual) (#33 TS definitions URL, #584 unpkg URL, #750 selectors link, #823 visitor types link, #278).
- [DOCS-04] (MINOR) Statements about defaults and semantics match the code path they describe. Known mismatches on master: css-modules.md:276-289 sets `animation`, `grid` and `customIdents` to `true`, which are the defaults (napi/src/lib.rs:731-734), so the "turning off" example turns nothing off and omits `container` (since #739); css-modules.md:221 says `[hash]` hashes "the full file path", but the path is made relative to `projectRoot` when one is set (src/css_modules.rs:288-296); minification.md:9 ties the optimizations to `minify`, but `transform()` always runs `StyleSheet::minify` and `minify` only configures the printer (napi/src/lib.rs:761-767; Devon on #1158); minification.md:219-245 and README.md:16 promise matrix conversion that is disabled (src/properties/transform.rs:60-119, tests commented out from src/lib.rs:13627, #288; verified on master: both examples print unchanged).
  verify: read the code path behind each changed sentence and run its example (DOCS-01).
- [DOCS-05] (MINOR) Lowering docs state what the output requires and where it is approximate: nesting lowering emits `:is()` even for targets without it (#202, #944, NEST-05); `light-dark()` lowering needs `color-scheme` on an ancestor (transpilation.md:336, #1196) and is resolved where a custom property is defined, not where it is used (#873, COLOR-14); `:dir()` becomes a `:lang()` heuristic (transpilation.md:412-430); logical lowering assumes a horizontal writing mode (EM-67, undocumented, LOGICAL-08); a new lowering that has a `Features` flag appears in the Feature flags list, so users can find the opt-out (Devon on #1287: "there is already a feature flag to disable LightDark").
  verify: compare the changed section with the lowering code and the area checklist items named here.
- [DOCS-06] (MINOR) Integration guides match the current APIs of the tools they describe: Vite `css.transformer: 'lightningcss'` plus the separate `build.cssMinify: 'lightningcss'` (Devon on #535), webpack's css-minimizer plugin, Parcel, and the Deno/browser wasm path with `await init()`; notes on what the WASM build supports (#1223) match what wasm/index.mjs exports.
  verify: compare each changed snippet with the tool's current docs and with the wasm/ entry points (manual) (#431, #675 duplicate of #798).
- [DOCS-07] (MINOR) Docs that describe behavior the PR changes are updated in the same PR: every hit of the changed property, function, option or CLI flag in website/pages/*.md and README.md still describes head's behavior.
  verify: `grep -rn '<name>' website/pages README.md` for each changed name; GEN-25 (#370: feature PRs update website/pages/*.md; transpilation.md lists every lowering).
- [DOCS-08] (MAJOR) Documented API behavior keeps working on head unless the PR declares the break: the transforms.md visitor and custom at-rule examples (its "Examples" section points at node/test/visitor.test.mjs), the bundling.md resolver contract, the css-modules.md configuration and the transpilation.md option examples produce the documented result.
  verify: B5 (visitor.test.mjs, customAtRules.mjs, bundle.test.mjs); PR probes for the documented CSS examples of the touched feature (#964: the documented `@mixin` example reordered declarations; #1005: the documented EnvironmentVariable example lost whitespace; both were code bugs found through the docs).
- [DOCS-09] (MINOR) Hand-maintained lists match their source: Feature flags (transpilation.md:93-118) vs node/flags.js (21 flags plus `Selectors`, `MediaQueries`, `Colors`); Syntax lowering sections (transpilation.md:159-582) vs what targets lower; Pseudo class replacement (transpilation.md:620-641) vs `OwnedPseudoClasses` (napi/src/lib.rs:644-650); Non-standard syntax (transpilation.md:643-659) vs `NonStandard` (napi/src/lib.rs:675-678); the README feature lists; the playground's hard-coded Draft syntax checkboxes (website/playground/index.html, playground.js; #1185 updated both). The include/exclude checkboxes are generated from `wasm.Features` (playground.js:348-369).
  verify: diff each list against its source in the head tree.
- [DOCS-10] (MINOR) Draft and non-standard syntax is documented as such: features behind `drafts`/`ParserFlags` appear under "Draft syntax" (transpilation.md:583-618) with the JS key and CLI flag (today only `customMedia`, although napi `Drafts` also has `scrollNavigationControls`, napi/src/lib.rs:666-671), `nonStandard` features under "Non-standard syntax", spec links point at the level that defines the syntax (custom media: mediaqueries-5 `#custom-mq`), and a standard feature is not called a draft or the reverse.

- [DOCS-11] (MINOR) CONTRIBUTING.md commands work on a fresh checkout: Node must satisfy `engines` (`>= 24.0.0` since #1388; CONTRIBUTING names no version), Yarn 1, the toolchain pinned in rust-toolchain.toml (1.96.0), `cargo test --all-features` as CI runs it (the documented plain `cargo test` skips the CLI integration tests, `required-features = ["cli"]` at Cargo.toml:109-112, and feature-gated tests such as `test_substitute_vars`), and binaryen `wasm-opt` for wasm builds (CI pins binaryen version_111; CONTRIBUTING suggests `cargo install wasm-opt`).

  verify: read the website diff for reflowed code fences and changed `.html` markup.
