# transform checklist (XFORM)

Covers `src/properties/transform.rs` (`Transform`/`TransformList` parse and the minify-only rewrites in `Transform::to_css` :1024-1230, `Translate`/`Rotate`/`Scale` :1437/:1523/:1634, `TransformHandler` :1725-1828), the PrefixHandler arm in `prefix_handler.rs:59-63` (transform-origin, transform-style, backface-visibility, perspective, perspective-origin), the `transform-origin` typing in `properties/mod.rs:1474`, unitless lengths in `src/values/length.rs:145-148`, transform prefix data in `prefixes.rs:338-409`, and motion path / `will-change` passthrough. Spec: `references/spec/anim-transforms.md` §1, §7, §8 (INV-TRF-001..016, INV-MOT-001/002, INV-WC-001).
Top failure modes: independently cascading properties folded into `transform` (#426, #1053, #1099, fixed by #1340); `none` turned into an identity value or back (#703, #1136/#1147); list shape changed so interpolation differs (#288/#694, skew renames, 3D collapse #239/#1080/#1335); invalid input repaired into valid input (#1199, transform-origin z).
Items describe head output. A `known: open-issue#N` or `open-bug` probe that is `still-different` on base and head does not FAIL an item unless the PR claims that bug. Transform rewrites run only when `dest.minify` is set: `test()`/`prefix_test()` and `print`/`lower` probes never show them, so every list-rewrite item needs a `minify` or `lower-minify` probe.

- [XFORM-01] (BLOCKER) `translate`, `rotate` and `scale` are never folded into `transform`, and a later `transform` (including `transform: none`) never drops or resets them: they cascade separately and compose in the fixed order translate, rotate, scale, offset, `transform`. A later duplicate `transform` still wins over an earlier one.
  verify: INV-TRF-006; probes transform/issues-important-individual-transform-preserved (fixed-by#1340), transform/issues-b3-individual-transforms-not-merged (#1099), transform/issues-important-transform-duplicate-last-wins (fixed-by b20cc5f, #499); history cc54e46 (v1.0.1) → #426 (still open on GitHub), #1053, #1099 → #1340 (40fb4ea, master, unreleased); `TransformHandler` arms at transform.rs:1742-1749; test with a second rule that overrides only one individual property; mutations reverse-decls, duplicate-nonadjacent -> O1; https://drafts.csswg.org/css-transforms-2/#ctm
- [XFORM-02] (BLOCKER) A transform list is never collapsed into `matrix()`/`matrix3d()` and a matrix is never decomposed: equal static matrices are not equal animations (`rotate(0)` → `rotate(360deg)` turns once; a matrix does not).
  verify: INV-TRF-001; probe transform/devon-rotate-over-360-not-matrix (6d46cce fixed #127); #288 fixed by #694 (matrix shortening disabled, transform.rs:60-119); maintainer-playbook "invalid shortening on print"; sample the keyframes with `animation: k 1s linear -0.5s paused` (L5) -> O1/O6; https://drafts.csswg.org/css-transforms-1/#matrix-interpolation, https://drafts.csswg.org/css-transforms-1/#interpolation-of-transforms
- [XFORM-03] (BLOCKER) Functions are renamed only within one transform primitive: translate*, scale* and rotate* share a primitive each, but `skew`, `skewX` and `skewY` share none, so `skewX(a)` never becomes `skew(a)` and `skew(0,a)` never becomes `skewY(a)` (pairing with the other endpoint switches to matrix interpolation).
  verify: INV-TRF-002 (NEW, fails on master: transform.rs:1204-1222, asserted at src/lib.rs:13612-13613; 50% of `skewX(10deg)` → `skew(20deg,30deg)` changes from `matrix(1.04064, 0.278839, …)` to `matrix(1, 0.267949, 0.267949, 1, 0, 0)`); probes transform/sat-skewx-not-rewritten-as-skew, transform/sat-skew-zero-x-not-rewritten-as-skewy, transform/sat-skewx-keyframe-vs-inline-from; WebKit matrix-interpolates from inline values even for skewX → skewX, so a Chrome/Firefox-only split is O9 judged by the spec, not noise; a PR that changes these expectations in src/lib.rs must flip them (T3); https://drafts.csswg.org/css-transforms-1/#transform-primitives (2D), https://drafts.csswg.org/css-transforms-2/#transform-primitives (3D)
- [XFORM-04] (MAJOR) 3D functions stay 3D unless the maintainer accepts the collapse: `translate3d(x,y,0)`, `scale3d(x,x,1)`, `rotate3d(0,0,1,a)`/`rotateZ(a)` keep the 3D-transformed status, `is2D` and the `translateZ(0)` layer hint; any 3D → 2D rewrite reaches its fixed point in one pass.
  verify: INV-TRF-005; probe transform/sat-translate3d-zero-keeps-3d-function (open-issue#239, also `idempotent`); print-time collapse at transform.rs:1061-1085, :1123-1203; #1080 dup, ecosystem EM-86 (DESIGN); PR #1157 closed (Devon: spec-equivalent, an opt-out is fine), master needs two passes (`translate3d(0,0,0)` → `translate(0,0)` → `translate(0)`; PR #1335 open makes it one): R2 / `idempotent`; `is2D` is not read by the oracle, so assert with `output-contains`/`output-not-contains`; https://drafts.csswg.org/css-transforms-2/#3d-transformed-element
- [XFORM-05] (BLOCKER) `none` and identity values are never interchanged: `translate: none` ≠ `0`, `scale: none` ≠ `1`, `rotate: none` ≠ `0deg`, `transform: none` ≠ an identity function, and `perspective: none` ≠ a length (any non-`none` value creates a stacking context and a containing block for fixed descendants). Individual properties serialize `none` only when `none` was specified.
  verify: INV-TRF-004; probes transform/sat-individual-identity-not-none, transform/community-prs-translate-scale-none-kept (fixed-by#703), transform/issues-b3-rotate-zero-not-none (fixed-by#1147, #1136); the probe needs a `dom:` line with a `position: fixed` child (7px → 15px shift when the containing block changes) -> O1/O6; https://drafts.csswg.org/css-transforms-2/#individual-transform-serialization, https://drafts.csswg.org/css-transforms-1/#transform-rendering
- [XFORM-06] (MAJOR) Identity functions inside a list are kept (`translate(0) rotate(45deg)` keeps both functions), because list length and function names decide how the list pairs with the other endpoint; only exact rewrites that keep the function count are allowed: `translate(x,0)` → `translate(x)`, `translateX(x)` → `translate(x)`, `scale(x,x)` → `scale(x)`, `scale(1,y)` → `scaleY(y)`, scale `%` → number, `rotate3d(1,0,0,a)` → `rotateX(a)`.
  verify: INV-TRF-003, INV-TRF-009; probe transform/sat-identity-functions-kept-in-list; test_transform; interpolation probe pairing the rewritten list with a different endpoint -> O1 (L5); https://drafts.csswg.org/css-transforms-1/#identity-transform-function
- [XFORM-07] (MAJOR) Invalid transform input stays invalid and never replaces a valid earlier declaration: unitless non-zero lengths (`perspective(1000)`, `translateZ(9)`, `translate(10, 0)`) are not repaired to `px`; unitless `0` is accepted only for lengths and for angles inside transform functions; negative `perspective` lengths are rejected and `perspective: 0` stays `0`.
  verify: INV-TRF-007, INV-TRF-014; probe values-numeric/ssv-unitless-translate-invalid (open-issue#1199, #682; length.rs:145-148 accepts quirky unitless lengths); #1329 (perspective 0 / negatives); WPT css/css-transforms parsing invalid cases (O7, `invalid-became-valid` absent); arch class A "invalid typed value wins"; https://drafts.csswg.org/css-values-4/#lengths, https://drafts.csswg.org/css-transforms-2/#valdef-perspective-length-0
- [XFORM-08] (MAJOR) `transform-origin`'s third value is always the z `<length>`, never a position offset: `left top 5px` keeps z = 5px, `top left 30px` keeps z, and invalid 3- and 4-value offset forms (`left 10px top 20px`, `bottom right 7px` as an offset) stay invalid. `perspective-origin` is a `<position>` with no 3-value form. Shortening to one value is correct only when the omitted component is `center` (#1027).
  verify: INV-TRF-012, INV-TRF-013 (fail on master: transform-origin typed as `Position`, mod.rs:1474 TODO; `bottom right 7px` → invalid `right 7px bottom`); probes transform/ssv-transform-origin-keywords-z, transform/sat-transform-origin-four-value-invalid, transform/sat-perspective-origin-three-value-invalid; WPT: 3 transform-origin and 8 perspective-origin invalid cases are still-different on master (O7); #1027 closed as not a bug; https://drafts.csswg.org/css-transforms-1/#transform-origin-property, https://drafts.csswg.org/css-transforms-2/#perspective-origin-property
- [XFORM-09] (MAJOR) `perspective(none)` inside a transform list keeps its meaning: if the PR types `perspective()`, it accepts `none` and prints it unchanged, never as `0` or a length.
  verify: INV-TRF-008 (kept today only because transform.rs:1013-1016 parses `<length>` alone and the list stays Unparsed); probe `transform: perspective(none) rotateX(45deg)` -> `output-contains:"perspective(none)"`; Chrome/Firefox support differs (O9); https://drafts.csswg.org/css-transforms-2/#funcdef-perspective
- [XFORM-10] (MAJOR) `rotate` axis normalization is exact and interpolation-neutral: only z-axis vectors (`0 0 1`, `0 0 2`, `0 0 -1`) collapse to a bare angle with the right sign; a negated x/y/z axis is rewritten only when the PR shows that interpolation against a non-normalized endpoint matches.
  verify: INV-TRF-010 (#1147, transform.rs:1576-1630: `-1 0 0 30deg` → `x -30deg`; to `x 720deg` at 50% the authored input gives Chrome 345deg, Firefox −15deg, WebKit 375deg, the output 345deg everywhere): an O9 split, decide against https://drafts.csswg.org/css-transforms-2/#interpolation-of-transform-functions; test_individual_transforms
- [XFORM-11] (MAJOR) Number printing keeps transforms renderable: ~6 significant digits (f32) never turn an invertible matrix into a singular one (singular = not rendered, interpolates discretely), angle conversions (`1rad` → `57.2958deg`) and math results (`scale(calc(100% / 3))` → `.333333`) stay within the oracle's noise, and rotations under 0.1° are read as raw values, not trusted to `noise`.
  verify: INV-TRF-011 (`matrix(1,1,1,1.0000001,0,0)` → singular); browsers.md G15 (noise hides < 0.1° rotations); `computed transform` is a resolved matrix with 6 significant digits in Chromium/Firefox, 6 decimals in WebKit; probe with a near-singular matrix and a large translation (`1234.5678` → `1234.57`) -> O1, read values from `lcr show`
- [XFORM-12] (MAJOR) `TransformHandler` keeps cascade order and idempotency with `var()`: an Unparsed `transform`/individual property flushes buffered typed values first, a prefix or value mismatch flushes, and a `var()` transform gets its `-webkit-` copy once, not again on every pass.
  verify: handler flush at transform.rs:1773-1789 (`get_prefixed`); integ on master: `transform:var(--t)` with `safari 8` gains a `-webkit-` copy each pass (R2 / `idempotent` probe; the same happens for `animation`); mutations var-before, var-after, prefixed-sibling, reverse-decls -> O1; RM-4 (buffering handlers reorder declarations)
- [XFORM-13] (MAJOR) PrefixHandler properties (`transform-origin`, `transform-style`, `backface-visibility`, `perspective`, `perspective-origin`) keep cascade order across `var()`: an in-place overwrite never moves a later typed value before an intervening Unparsed one (`perspective:10px;perspective:var(--p);perspective:20px` must not become `perspective:20px;perspective:var(--p)`).
  verify: probe rule-merging/arch-props-values-prefix-handler-in-place-update-reorders-unparsed (fails on master; prefix_handler.rs:24-38 overwrites the earlier slot); var-before/var-after reuse the same value so they cannot show it: write a probe with three distinct values; arch class C "in-place overwrite"
- [XFORM-14] (MAJOR) Prefixing follows the data and keeps author fallbacks: `-webkit-transform`/`-webkit-transform-origin` only for Chrome 4-35, Safari 3.1-8, iOS 3.2-8.1, Opera 15-22, Android 2.1-4.4.3 (`-moz-` Firefox 3.5-15, `-ms-` IE ≤ 9, `-o-` Opera 10.5-12; perspective/transform-style `-webkit-` Chrome 12-35, Safari 4-8); prefixed copies print first; prefixed and unprefixed declarations with different values keep their order; an authored prefixed copy equal to the unprefixed value is dropped only when no target needs it (#396); transforms inside `@keyframes` are prefixed in every keyframes copy.
  verify: INV-TRF-015 (transform.rs:1755-1768), INV-TRF-016 (a 3D-only fallback for 2D-only UAs may be deduped); prefixes.rs:338-409 is generated (B11, build-prefixes.js); default `lower*` targets (legacy-2020) need no transform prefix, so use `safari 8` targets with `output-contains` (no engine profile is that old); mutations prefixed-sibling, retarget-legacy, retarget-none; idempotency on the prefixed output (#403 lesson)
- [XFORM-15] (MAJOR) Individual transforms are never lowered into `transform` for old targets (Chrome < 104, Firefox < 72, Safari < 14.1): folding is never exact (#1340), so any PR that adds or removes such lowering is a maintainer decision stated in the PR, checked in Chromium 97 (`legacy-2021`, which lacks individual transforms).
  verify: #1340 also ended the accidental lowering that cc54e46 provided (regressions.md TR-1); legacy engine profile legacy-2021 -> O4 (differences that match on base and head are pre-existing); no compat key for individual transforms exists at cbeaf83: a PR that adds lowering adds one, and it must not count partial/prefixed BCD entries (B11)
- [XFORM-16] (MAJOR) Motion path and `will-change` pass through verbatim: `offset` keeps its fixed component order and resets omitted parts, `offset-position: normal` ≠ `auto`, `offset-rotate: auto` ≠ `0deg`, the offset transform is never folded into `transform`, and `will-change` values are never removed or deduplicated (they create stacking contexts and containing blocks).
  verify: INV-MOT-001, INV-MOT-002, INV-WC-001; probe transform/sat-motion-offset-shorthand-passthrough (guard); a PR that types `offset*` or `will-change` needs WPT css/motion parsing files (O7) and a `dom:` stacking probe (O1/O6); https://drafts.csswg.org/css-transforms-2/#ctm
- [XFORM-17] (MAJOR) Each transform rewrite in the diff is backed by evidence the oracle can see: a sampling probe (`animation: k 1s linear -0.5s paused` with the rewritten list in a keyframe, or `@starting-style` + `transition: transform 1000s step-end`) for interpolation, a `dom:` line with a positioned child for stacking or containing-block changes, and output assertions for 2D/3D status; differences are compared within one engine, never across engines.
  verify: anim-transforms §8 (L5: list rewrites, 3D collapse and keyframe contents are invisible at rest; mutations never touch `@keyframes` contents); computed `transform` resolves percentages against the box, whose height differs per engine (browsers.md: 18 vs 22px), so compare base and head per engine; `translate: 100px 0%` vs `100px` shows as `different` (not normalized): classify only with a spec anchor after checking interpolation; visual area -> screenshot hash (O6)
