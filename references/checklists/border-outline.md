# border-outline checklist (BORDER)

Covers `src/properties/border.rs` (BorderHandler, which also drives the border-image and border-radius sub-handlers), `border_image.rs`, `border_radius.rs`, `outline.rs`. Spec: `references/spec/images-effects.md` §5 (D2, D15, D16, D19, D20, D23, INV-BORDER-*, INV-UI-*). box-shadow is in the effects-masking checklist.
Top failure modes: `border` vs `border-image` reset order (#103, #187, D2); border-image serialization that is empty or uses the wrong property's defaults (#1052/#1146, D15); logical border/radius lowering lost or misplaced after nested rules (#1049, #1246).
Items describe head output. A `known: open-issue#N` or `open-bug` probe that is `still-different` on base and head does not FAIL an item unless the PR claims that bug.

- [BORDER-01] (BLOCKER) `border` resets all five `border-image-*` longhands in output order: a border-image written before `border` is dead and one written after stays after, for typed `border`, for `border: var(...)` (unparsed), and when side longhands are collapsed into `border`; `border-top`, `border-width` and the other border shorthands never reset border-image.
  verify: INV-BORDER-001; probes border-outline/sie-border-var-shorthand-resets-border-image (Chrome maxdiff 255), border-outline/arch-props-values-border-longhand-collapse-resets-border-image (only the typed `Border` arm resets the border-image handler, border.rs:710-723; the Unparsed arm :725-728 pushes `border:var()` and the border image is flushed after it at finalize, :742-746), border-outline/sie-border-shorthand-resets-border-image (guard); history #103 (28bf5af), #187 (957b1cd); mutations var-before, var-after, reverse-decls -> O1; https://drafts.csswg.org/css-backgrounds-3/#border-shorthands
- [BORDER-02] (BLOCKER) `border-image` (and `mask-border`/`-webkit-mask-box-image`, which share the serializer) never prints an empty value: all-initial prints `none`, and each single non-default component prints a valid value.
  verify: INV-BORDER-004; probes border-outline/issues-b3-border-image-none-not-empty, border-outline/arch-props-values-border-image-none-serializes-empty, border-outline/pr1336-border-image-none-not-empty (open-issue#1146, dup #1052; PR #1336 approved, needs a rebase); O3 (`border-image:` is rejected, so an earlier border image survives in the engine); border_image.rs:295-335; the width-omitted form keeps `//` (`30 // 2px`, INV-BORDER-005); the leading space in `border-image: 30 round` is cosmetic only; https://drafts.csswg.org/css-backgrounds-3/#border-image
- [BORDER-03] (MAJOR) Logical border and border-radius lowering emits its physical or `:dir()`/`:lang()` rules for the declaring rule only: nothing is dropped after a nested rule (#1049), nothing is attached to the next sibling selector (#1246), and `!important` survives the lowering.
  verify: probes nesting/issues-important-nested-decl-logical-radius-dropped, nesting/pr1123-logical-after-nested-rule (open-issue#1049), nesting/issues-important-nested-decl-logical-fallback-hoisted, logical/nested-declarations-logical-fallback-on-parent (open-issue#1246; both regressions of 6c465c1, v1.30.0; PRs #1123, #1061), logical/arch-core-important-logical-lowering-keeps-important (arch-core N5); NestedDeclarationsRule::minify never drains the side rules (nesting.rs:73-84); mutations nest, important, engine-legacy-2021 -> O4
- [BORDER-04] (MAJOR) Default omission uses the defaults of the property being printed: an explicit slice in `-webkit-border-image` is kept (the legacy property implies `fill` when a slice is given), `-webkit-mask-box-image` (Blink initial slice `0 fill`, width `auto`) and `mask-border` (slice `0`, width `auto`) never use the border-image defaults (slice `100%`, width `1`).
  verify: INV-MASK-007; probes border-outline/issues-b3-webkit-border-image-explicit-slice (Chrome 156 computes `100% fill`), effects-masking/issues-b3-mask-box-image-default-slice (both equivalence-only, fail on master: border_image.rs:295-335 compares against border-image defaults for every caller); https://drafts.csswg.org/css-masking-1/#the-mask-border-slice
- [BORDER-05] (MAJOR) With targets, BorderImageHandler keeps author order and per-prefix values: a compatibility flush never prints an earlier `border-image` before a pending `border`, `-webkit-border-image` and `border-image` with different values are not merged into one value, and gradient fallbacks appear only in the property with the matching prefix.
  verify: repros (verified on master with the base adapter) `border:1px solid;border-image:url(a.png) 30 round;border-image:url(b.png) 30 space` (chrome 50 -> `border-image:url(a.png) 30 round;border:1px solid;…`, so Chrome 50 loses the image) and `-webkit-border-image:url(a.png) 30;border-image:url(b.png) 30` (no targets or chrome 10 -> both `url(b.png)`); border_image.rs:416-443 (`flush!` only on incompatible values, prefixes OR'd), :522-530 (`fill` disables prefixing; fallback prefix matching); mutations prefixed-sibling, retarget-legacy; no installed engine needs `-webkit-border-image`: use output assertions
- [BORDER-06] (BLOCKER) Zero lengths keep their unit where `<number>` is also valid (`border-image-width`, `border-image-outset`, `mask-border-width/-outset`): `0px` never prints as `0`, because a number multiplies border-width and does not interpolate with lengths; `border-image-slice: 0%` never becomes `0` either (they interpolate differently).
  verify: INV-BORDER-002/003; probes border-outline/sie-border-image-width-zero-length-stays-length, border-outline/sie-border-image-outset-zero-length-stays-length (fail on master: `border-image:url(a.png) 30 / 0px / 0px` -> `30/0/0`; Chrome 156 paused animation gives 10px at 50% for `0 -> 10px`, 5px for `0px -> 10px`); same class as `tab-size: 0px` -> `0` (text/sft-tab-size-zero-length-stays-length); https://drafts.csswg.org/css-values-4/#lengths
- [BORDER-07] (BLOCKER) Border color fallbacks (lab/oklch/p3 to rgb) never panic and keep `currentcolor`, system colors and `light-dark()` sides as authored.
  verify: probe border-outline/community-prs-border-color-oklch-currentcolor (PR #1311 class: panics on master in CssColor::get_fallback, color.rs:517-519); #831 (`light-dark()` in `border-color` with lowering, UNVERIFIED, probably the #821 custom-property scoping limit); R1; mutations retarget-legacy, engine-legacy-2023
- [BORDER-08] (BLOCKER) `border-radius` collapse and expansion keep corner order (top-left, top-right, bottom-right, bottom-left) and the axis split: longhand `a b` is horizontal/vertical, shorthand `a b` is per corner, `/` separates horizontal from vertical radii.
  verify: INV-BORDER-007; #308 (bottom-left/bottom-right swapped; the existing test encoded the wrong answer, so derive expectations from the spec); test_border_radius; mutation reverse-decls -> O1/O6; https://drafts.csswg.org/css-backgrounds-3/#border-radius
- [BORDER-09] (MAJOR) Collapsing sides into `border`/`border-<side>` never drops a component that is not initial in that context: the width is kept when the style is `none`/`hidden` (`border:5px none` keeps computed 5px for a later `border-style:solid`), `border:none` stays distinct from `border:0`, and no stray separator appears with any component omitted.
  verify: INV-BORDER-006; `border:5px none` -> `border:5px` on master (width kept); `.a{border:none}.b{border-style:solid}` keeps `border:none` (EM-54, passes on master); #138 (stray space, fixes #130), 1f66776 (#154: `border:none green` -> `border:green`); mutation reverse-decls -> O1; https://drafts.csswg.org/css-backgrounds-3/#border-width
- [BORDER-10] (BLOCKER) Border and outline values browsers reject stay invalid and do not override an earlier valid declaration: `outline-style: hidden`, negative widths, radii and `border-spacing`, unitless non-zero lengths (`border-width:3`, `border-radius:5`, `outline-width:2`), `hairline` where engines lack it.
  verify: INV-UI-001, INV-GEN-002; probes border-outline/spec-layout-outline-style-hidden-overrides-valid (OutlineStyle reuses LineStyle including `hidden`, outline.rs:27-32), values-numeric/issues-b1-unitless-number-non-quirky-context (open-issue#682; master prints `3px`, `5px`, `2px`); `property_range_test` cases from #1329 (NonNegative, unreleased); WPT css/css-ui/parsing/outline-style-invalid.html, css/css-backgrounds/parsing/*-invalid.html via O7 `invalid-became-valid`; https://drafts.csswg.org/css-ui-4/#outline-style
- [BORDER-11] (MAJOR) Longhands with CSS-wide keywords are not collapsed into a shorthand that resets more: `border-width/style/color: inherit` never becomes `border: inherit` (that also inherits border-image); mixed keyword and typed sides stay longhands.

  verify: INV-BORDER-008, INV-GEN-001; master already hoists `corner-shape` and `border-top-radius` before a deferred `border-radius`/`border` (benign today: no reset relation, or Chrome 156 lacks the property); declaration.rs:583-611; mutation reverse-decls; Chrome 156 has `corner-shape` (139) but not `corner`, so O1 may be blind: decide against https://drafts.csswg.org/css-borders-4/#corner-shorthands
- [BORDER-13] (MAJOR) Outline collapse keeps the color: `outline-style:auto` with an explicit `outline-color` (including `currentcolor`) is not collapsed into `outline:auto`, which sets `outline-color:auto` (the accent color) under css-ui-4; a newly typed outline longhand (e.g. `outline-offset`, #1048) is owned by OutlineHandler or keeps its source position.
  verify: INV-UI-002; master collapses `outline-style:auto;outline-color:currentcolor;outline-width:3px` into `outline:3px auto` (verified; `CSS.supports('outline-color','auto')` is false in Chrome 156, Firefox 157 and WebKit 27.2, so the delta is spec-only: classify NEEDS_MAINTAINER_DECISION); test_outline; mutation reverse-decls; outline.rs:57-61 (`shorthand_handler!`); https://drafts.csswg.org/css-ui-4/#outline-color
