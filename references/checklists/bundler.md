# bundler checklist (BUNDLE)

Covers `@import` bundling and dependency analysis: `src/bundler.rs` (parallel `load_file`, `order`, `inline`, `SourceProvider`/`resolve`, `ResolveResult` externals), `src/dependencies.rs` (`analyzeDependencies`), `src/rules/import.rs`, `src/values/url.rs` (url dependencies and placeholders), and napi `bundle`/`bundleAsync` with JS resolvers.
Top failure modes: (1) `@import` conditions (layer, media, supports) combined lossily or reordered (five combinations, all unfiled and verified on master); (2) output and source-map order depend on parallel load order or HashMap iteration (#1167, #137); (3) dependency metadata loses semantics (no layer, #1074; fragment and data URLs; placeholder format).
Evidence: the oracle does not follow `@import` (L7) and probes are single-file, so bundler behavior needs `bundler::tests` cases (`fs!{}` TestProvider, src/bundler.rs:957-1064) or `node/test/bundle.test.mjs`.

- [BUNDLE-01] (BLOCKER) Every `@import` condition survives inlining: named, anonymous and nested layers (`parent.child`), `supports()`, and media (the AND of parent and child, including `not` qualifiers), and `@layer` statements inside a layered child keep their names and positions.
  verify: `bundler::tests::test_bundle` (src/bundler.rs:1066-1902) with one case per combination; on master an anonymous parent layer drops the layer of an unlayered child (bundler.rs:502-523), non-leading statements are double-prefixed (printed as `@layer p.x` inside `@layer p {}`, i.e. `p.p.x`, :476-482), and `not print` ANDed with a child query means NOT(print AND …) (`MediaQuery::and`, media_query.rs:367-417).
- [BUNDLE-02] (BLOCKER) Duplicate imports keep browser cascade semantics: the last instance decides the position (`order`, src/bundler.rs:668-711), and duplicates that differ in layer, media or supports are neither collapsed into one copy nor ORed into one position.
  verify: bundler tests `@import a print; @import b; @import a screen` and `@import a; @import a layer(x)` asserting order and both copies (both lossy on master; duplicate handling at :364-411); use output assertions, since the oracle cannot emulate print media (L6).
- [BUNDLE-03] (MAJOR) Output is deterministic and independent of rayon completion order: the source index assigned at registration (src/bundler.rs:413-414) is the index the source map uses (`add_source` at :463-465 runs in completion order and its result is ignored), no HashMap iteration reaches the output, and two runs give identical code and maps.
  verify: run the PR's bundler tests and node bundle tests twice; GEN-12 (#1167 open; #137 surfaced by #772 as nondeterministic `@supports` order; 8b34d7e established load, then order, then concatenate).
- [BUNDLE-04] (MAJOR) External imports follow the #880 contract: a resolver may return `{external}` (`ResolveResult`), externals before every bundled import keep their order, an external after a bundled import is `ExternalImportAfterBundledImport` (src/bundler.rs:196, :762), and the serde attribute and TS types match (`cfg_attr(feature = "serde")`, #1251; node/index.d.ts, #1261).
  verify: bundler test at src/bundler.rs:1671; node bundle.test.mjs "external import"; B8 compiles no bundler code, so also run `cargo check -p lightningcss --no-default-features --features bundler,sourcemap`.
- [BUNDLE-05] (MAJOR) `analyzeDependencies` metadata carries every cascade-relevant condition of a removed `@import` (url, media, supports, and layer, which is missing today: src/dependencies.rs:46-57, #1074), and placeholders are printed as `url("<placeholder>")` with double quotes.
  verify: `dep_test` cases (src/lib.rs:30371-30403) in the PR; node tests asserting `dependencies` (Vite string-replaces the placeholders and escapes `"` assuming that format).
- [BUNDLE-06] (MAJOR) URL dependencies cover every url-bearing value and only real resources: fragment-only `url(#id)` and `data:` URLs are not dependencies (f6f1673, #1055), a relative `url()` in a custom property stays an error under analyzeDependencies (3374158 for #81, #1154), `image-set()` string URLs are collected (8378ae2 for #76), and `loc` points at the URL token (#1149: src/values/url.rs:33-38 records the location before whitespace is skipped).
  verify: `dep_test`/`dep_error_test` in the PR; node bundle and visitor tests.
- [BUNDLE-07] (MAJOR) Inlined child content is valid where it lands: leading `@layer` statements are hoisted, and a child's `@namespace`, `@charset` or `@import` never ends up inside the `@layer`/`@media`/`@supports` wrappers (the inline loop stops at the first other rule, src/bundler.rs:713-820; wrappers are layer, then media, then supports, :791-813).
  verify: bundler test with a child that contains `@namespace`; strict re-parse of the bundled output with errorRecovery off.
- [BUNDLE-08] (MAJOR) A child file that starts with U+FEFF does not leave the BOM in the middle of the output, where it joins the next selector and the rule matches nothing (verified with `bundle()` on 1.33.0; docusaurus#12358 shipped a dropped `@font-face` this way).
  verify: bundler test with a BOM-prefixed child and output assertions, not the oracle (a `<style>` element keeps U+FEFF); a probe cannot start at byte 0 (#338 open; PR #1301 strips only a leading BOM).
- [BUNDLE-09] (MAJOR) Resolver and provider behavior is unchanged for existing callers: `FileProvider::resolve` stays `with_file_name(specifier)` (src/bundler.rs:166-169), JS `read`/`resolve` throws and non-string returns become JS errors with location info, `bundle` and `bundleAsync` give the same output, and relative `url()`s in imported files stay as written (#181 open by design: callers rebase them through `analyzeDependencies` placeholders), unless the maintainer agreed to change that.
  verify: node bundle.test.mjs (15 tests: throws, async throws, non-string returns, location info); B5.
- [BUNDLE-10] (MAJOR) Nothing new can panic on a bundler worker: rayon loading and napi threadsafe-function paths return errors (release builds use `panic = 'abort'`, Cargo.toml:126-129, which kills the Node process), and the Rust bundler stays synchronous (the tokio rewrite #196 was rejected for #263).
  verify: R1; risk flags `added-unwrap`/`added-panic` on src/bundler.rs; node async bundle tests run repeatedly (#1164 random silent crash, open).
- [BUNDLE-11] (MAJOR) CSS modules and custom media work across files: each file keeps its own hash and `[content-hash]`, `composes … from` keeps the first instance, exports of imported files are not re-exported (#1034), and `@custom-media` defined in one file applies in another only with the flag.
  verify: bundler::tests::test_css_module (src/bundler.rs:1904-2161); `bundle_custom_media` cases (:1000-1030).
- [BUNDLE-12] (MAJOR) Visitors and custom at-rules see bundled sheets correctly: bundler-produced `CssRule::Ignored` placeholders survive a JS StyleSheet visitor round trip (the hand-written CssRule deserializer requires `value` before dispatching on `type`, src/rules/mod.rs:202-252, `missing_field("value")` at :246; #1104 open), and visitors run once over the bundle.
  verify: node visitor.test.mjs "works with bundler" and "works with async bundler", customAtRules.mjs "bundler"; VISIT-01.
- [BUNDLE-13] (MINOR) Bundle errors name the failing specifier and file with a location, and a child's syntax error maps to the child's filename.
  verify: node bundle.test.mjs "read throw with location info" and "should throw with location info on syntax errors"; the bundler `error_test` helper (src/bundler.rs:1032-1047).
