# gradient-image checklist (IMG)

Covers `src/values/gradient.rs`, `src/values/image.rs`, `src/values/url.rs` (and `resolution.rs` inside `image-set()`): gradients, legacy prefixed gradients, `-webkit-gradient()`, `image-set()`, `url()`. Spec: `references/spec/images-effects.md` §1-§3 (D6-D14, INV-GRAD/IMG/URL).
Top failure modes: standard-syntax rules applied to legacy prefixed gradients (#918, #1107, #936 regression); gradient rewrites that are not exact (flip #1220, 50% hint, interpolation space); image-set lowering that drops the only working fallback or emits syntax old engines reject (#252, #262/#264, #1286).
Items describe head output. A `known: open-issue#N` or `open-bug` probe that is `still-different` on base and head does not FAIL an item unless the PR claims that bug; a PR that claims it must turn it `fixed` (A2). Gradient-only deltas are judged by the case's `visual` verdict (O6 pixels), not computed strings (INV-GRAD-017).

- [IMG-01] (BLOCKER) Authored `-webkit-`/`-moz-`/`-o-` linear gradients keep their 2011 meaning in print and minify: start-side keywords are not printed as standard angles (`left` is not `270deg`), `bottom`/`180deg` are not dropped as the default, and stops are not reversed for `top`/`0deg`.
  verify: INV-GRAD-015; probes gradient-image/webkit-linear-gradient-legacy-keyword-minify, gradient-image/prefixed-gradient-minify, gradient-image/prefixed-gradient-print, gradient-image/authored-legacy-gradient-bottom-keyword, gradient-image/authored-legacy-gradient-keywords-minify, gradient-image/legacy-webkit-gradient-keyword-minify (all open-issue#1107); O1 + O6; the code must branch on `is_prefixed` in LinearGradient::to_css gradient.rs:268-330 and LineDirection::to_css :501-543; a fix legitimately changes src/lib.rs:14210-14213 (expects `-webkit-linear-gradient(bottom, yellow, blue)` to print `-webkit-linear-gradient(#ff0,#00f)`, dropping `bottom`: T4 delta INTENDED); https://www.w3.org/TR/2011/WD-css3-images-20110217/#linear-gradient-syntax
- [IMG-02] (MAJOR) Generated prefixed gradient fallbacks are correct in compact output: `to <side>` becomes the opposite start side (#918), every angle becomes `(90deg - a) mod 360` (`540deg` gives `270deg`, not `90deg`), the legacy default direction is not flipped when minified (#936 regression, v1.30.0), and `-webkit-radial-gradient` uses the legacy `<position>, <shape> <size>,` form, never `at`.
  verify: INV-GRAD-015; probes gradient-image/legacy-prefix-direction-inverted (fixed-by#936), gradient-image/prefixed-gradient-default-direction-minify (chrome 100: Chrome 100-112 use the `-webkit-` copy made for `image-set()`), gradient-image/prefixed-gradient-old-webkit-minify, gradient-image/legacy-angle-over-450deg, gradient-image/webkit-radial-gradient-legacy-position (the last four fail on master); output assertions only (no installed engine renders Chrome <= 25); PR tests must lower with minify (`minify_test_with_options_and_browsers`), not only the pretty `prefix_test`; gradient.rs:551-602 (convert_to_legacy_*), :368-417 (radial ignores the prefix)
